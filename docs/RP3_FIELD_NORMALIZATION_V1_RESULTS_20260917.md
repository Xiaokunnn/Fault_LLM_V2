# RP3 请求字段归一化：三种子构建集结果

执行日期：2026-09-17。**欠填和指针指标改善，但新增教师空集误填，未通过预声明的整体改善条件。**
没有据结果调整种子、阈值、早停或协议；没有采用本轮模型替换基线或进入部署。

## 1. 固定设计与证据入口

- 监督审计：[`audit.md`](../results/experiments/research_point_3/field_supervision_audit_v1/audit.md)、同目录`audit.json`。
- 配对结果：[`summary.md`](../results/experiments/research_point_3/field_normalization_v1/summary.md)、同目录`summary.json`和`summary.csv`。
- 源码/配置冻结：结果目录`protocol_snapshot.json`、`source_snapshot.zip`；日志`logs/rp3_field_normalization_v1_20260917.log`及各新臂`execution.log`。

C0复用三个种子7042027/7042028/7042029的A3全字段模型，不重训。
C1只将field-state/cardinality各自的CE由`0.25×请求均值 + 0.75×非请求均值`
改为`0.5×请求均值 + 0.5×非请求均值`；非请求字段仍受监督，任务总权重仍为各0.6。
新增逐epoch审计只读取已产生的detached logits，不改变随机状态、更新或早停。
冻结教师、165条构建轨迹、129/36划分、特征、架构、运行环境和其余设置均与同种子A3核对一致。
这是A3单因素对照，不能称为M0复合目标或完整Route系统的复跑。

## 2. 监督和损失核查

| 子集 | 请求字段零数量 | 非请求字段零数量 | 全字段零数量 |
|---|---:|---:|---:|
| train原始 | 5/32 | 96/96 | 101/128（78.91%） |
| train派生 | 32/97 | 291/291 | 323/388（83.25%） |
| train全部 | 37/129 | 387/387 | 424/516（82.17%） |
| validation原始 | 1/8 | 24/24 | 25/32（78.12%） |
| validation派生 | 11/28 | 84/84 | 95/112（84.82%） |
| validation全部 | 12/36 | 108/108 | 120/144（83.33%） |

非请求槽位占75%，但A3最佳模型上其实际cardinality CE贡献仅约29%–35%，field-state CE贡献约43%–52%。
将请求字段本身为空的槽位也计入，全部零数量槽位仅贡献29.54%–35.47%的cardinality CE、47.83%–56.30%的field-state CE。
这表明数量损失主要仍来自非空请求目标；字段状态损失约一半来自空槽位，未显示与82%标签占比相当的压倒性贡献。
该分解由训练前审计JSON中的组内CE求和得到，另存为结果目录`zero_label_loss_shares.json`，没有重新推理或训练。
因此不能把大量空标签等同于损失或共享参数梯度占主导；本轮没有测量参数梯度分解。
请求组在旧平均公式中权重较小，与“旧模型当前主要损失来自非请求字段”是不同命题。

A1/A2/A3九次训练均选择epoch 1；没有字段损失的A1/A2也如此。
A3从epoch 1到6的加权验证排序损失增加0.7438/0.8099/0.8017，
support、field、cardinality合计下降约0.2758/0.3252/0.3123，导致总验证损失变差。
这解释总损失早停的数值选择，不证明排序退化的唯一根因，也不能从损失推断旧模型后续任务准确率。
旧臂只有最佳checkpoint，未补造后续epoch预测。

## 4. 误填约束：本轮未通过

| 种子 | 原始validation教师空集误填 C0→C1 | 完整validation教师空集误填 C0→C1 | 完整validation零可用证据误填 C0→C1 |
|---|---:|---:|---:|
| 7042027 | 0/1→1/1 | 0/12→3/12 | 0/8→0/8 |
| 7042028 | 0/1→0/1 | 0/12→0/12 | 0/8→0/8 |
| 7042029 | 0/1→0/1 | 0/12→0/12 | 0/8→0/8 |

7042027的三条误填为：

- `RP3-CQ-F03-SYM-original`：2个可用候选，教师选集为空，学生填入2个。
- `RP3-CQ-F03-SYM-original-remove-a67ebfc6429cf131`：1个可用候选，教师选集为空，学生填入1个。
- `RP3-CQ-F10-MAINT-original-remove-b00338bd909055ac`：1个可用候选，教师选集为空，学生填入1个。

这说明“可用候选不为空”不能替代“足以形成教师支持的回答”。上述是教师相对误填，不直接等同事实错误。
零可用证据时的输出约束仍有效，但不能掩盖有候选、无教师答案时的误填。
原始validation没有零可用证据样本，该项为0/0（NA），不能写成原始集上已经证明零风险。
三条失败中含原始查询及其派生版本，不能视为三个独立病例。

预声明四项条件中，Pointer F1提高、raw零预测降低、raw基数准确率不降低均满足，
“每个种子的教师空集误填不增加”失败。最终状态为`improvement_not_established_under_prespecified_rule`。

## 5. 新臂逐epoch观察与下一步

新臂分别运行7/6/6 epochs，按原定总validation loss选择2/1/1；未改用表现更好的后期epoch。
7042027总损失epoch 1→2为2.5258→2.5209，之后排序损失上升使总损失变差。
7042028和7042029到epoch 6的排序损失分别从1.1198/1.0888上升到1.9316/1.8969；
虽然请求字段状态CE下降，总损失仍从2.5064/2.4491上升到3.0238/2.9473。
请求cardinality CE下降幅度小且波动，不能把整体field CE下降写成请求数量已学好。

新臂后期Pointer F1有时更高，同时多个epoch也出现教师空集误填。
例如7042027 epoch 4的F1为0.6000，但原始教师空集仍1/1误填；不能据此事后改选模型。
因此仅延长训练或按回答数量/F1挑checkpoint不能解决本轮质量约束。

下一步优先为**有候选但教师空集的支持/字段/数量门控联合诊断**，
并将排序损失与任务质量不一致作为单独的模型选择研究问题。若开启新训练，先另立单因素、三种子协议，
保留当前全部失败，不能直接继续调本轮权重、挑种子或选后期checkpoint。
MP008覆盖问题仍独立存在；本轮未加载MP008、未拟合Route/阈值、未量化或部署。
