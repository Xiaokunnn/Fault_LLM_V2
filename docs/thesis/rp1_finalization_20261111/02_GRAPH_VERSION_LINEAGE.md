## 2. 原始提议、缓存、审计不是同一对象集合

全语料抽取摘要`qwen3_7_max_full_corpus_v1/extraction_run_summary.json`记录1889页完成、8071条原始提议、64条接口规范化排除、8007条保留候选。实体类型、关系词表或字段契约未满足的提议，不能自动成为规范候选。因此8071不是8007的笔误。

论文和原审计图的8003条记录，是后续修复、方向规范化、证据处理和身份去重后的审计池；原决策为1698自动证据准入、881隔离、5424拒绝。后来的`qwen3_7_max_full_corpus_v1_evidence_repaired/candidate_triples.evidence_repaired.jsonl`也为8003条，但不能据行数相同断言与原审计池逐字段相同。扩图读取的是后者，固定候选门控消融读取的是`KG_v1_raw/source_records.jsonl`。本包同时登记两个输入哈希。

8071→8007有抽取摘要可查；8007与8003之间存在载荷和身份变化，不能仅用净差4推断“只有4条被删除”。源文字面实体、规范化源语实体、中文候选实体和发布实体也不是同一去重口径。表格中给出原始表面计数时，列名明确标为`typed_exact_source_surface_entities`，不能与2022/2150个中文发布实体直接作质量比较。

## 3. standard1326如何产生

历史1698条准入记录的证据决策保持不变，术语治理分别得到strict208、conservative620和standard1326。standard统一采用0.90局部术语阈值，结合已有词典、中文名称完整性、同类型一致性及保护字符串规则。1326/1698=78.09%是术语发布保留比例，不是事实准确率。

strict208→standard1326增加1118条记录、1078项Claim和1741个实体，反映术语准入策略变化，不能称为重新抽取了1118条或新增算法纠正了1118条错误。保留conservative620资产供历史说明，但后续研究不要求用户在多个应用图之间选择。

## 4. expanded1456如何产生

构建脚本`build_rp1_graph_expansion_v1.py`在8003条既有记录上执行有限原生角色恢复，复用标准图1326条，再新增130条：

| 新增记录原决策 | 数量 |
| --- | ---: |
| 拒绝 | 98 |
| 隔离 | 27 |
| 历史证据准入但术语未发布 | 5 |

因此1456中有125条来自历史未准入部分，不能写成“1698条中的1456条”。按扩图输入记录链接，主图谱与历史准入集合对应1331条，另125条依据独立扩展契约加入。这是记录谱系关系，不是新旧事实质量排序。

130条新增记录对应127个规范关系键，其中119个标准图原先没有；9条新增记录为已有关系提供补充证据。故记录增量130、Claim净增119不是矛盾。新增主要来自87条表格角色恢复、43条正文角色恢复；只有7条关系名称变化，4条同时交换端点，不能将130条统称为方向纠错。

全量决定为1326复用、3996未扩展适用范围、253保留已有模型否决、2254缺少唯一明确角色证据、40术语阻断、4同关系同页重复、130新增，总计8003。没有新增模型调用。

主图使用独立的有限源文角色契约，不是对新增130条重新运行历史同模型双提示核验。`expansion_validation`是新验证说明；`expansion_prior_validation`是原决策。若干根级`validation_status`、`relation_entailment_validation`和`final_confidence`仍为历史值，不能当成扩展验证的结果。

## 5. ID与条件语义

expanded实体、Claim和断言分别使用`EXE-`、`EXC-`、`EXA-`命名空间。1326条复用记录的根级旧ID仍被保留，而`expanded_*`统一指向新图。实际核对发现1326条记录根级`claim_id`与`expanded_claim_id`不同；未来读者必须使用后者连接1400项Claim。

新表[version_record_id_crosswalk.csv](tables/version_record_id_crosswalk.csv)保存1456条记录的来源父ID、标准/严格Claim ID与expanded ID。标准发布重建过ID，不能强制按新旧`triple_id`相等连接。对复用部分，采用文档、物理页、源文两端、关系、证据组成的精确来源键，验证其在扩图输入中唯一；对新增部分，采用明确的`expansion_parent_triple_id`。1326条基线原字段逐一保持不变。

1400项Claim是相同规范化两端与关系的**主张族**，条件与模态保留在断言层；不代表1400项相互独立、无条件成立的工程事实。构建摘要另有1414个上下文组合计数，但它不是实际`claims.jsonl`行数，不能替换1400。

130条新增有显式`conditions_source`和模态；1326条复用断言的`conditions_source`为null、模态为`legacy_unspecified`。这表示没有在该新字段中显式结构化，并不表示源文无条件。全图也没有统一显式极性字段。未来接口必须保留未知，不得补成“无条件、确定、正向”。

## 6. 最终研究图的实际质量边界

80条冻结样本的单AI、非盲源文审查发现：原图40条的源文支持为36/3/1，条件合格为23/13/4；新增40条分别为38/2/0及26/11/3。新增同一批40条在恢复前的条件合格为15/22/3，配对有11条从缺陷转为合格，关系支持数没有增加。

已知缺陷包括B06禁止无液运行却被表成正向工况、A14把修复后果的措施连到诱因、A24将对中状态当物理部件，以及型号/章节条件缺失。图冻结后未据抽查结果删除样本。采用1456作为主图谱意味着统一研究对象和版本，不意味着取消这些缺陷或完成生产验收。

本包不把非盲AI样本比例外推为正式全图准确率，也不将1456/8003作为与1698/8003同契约的成功率比较。expanded1456的CQ和下游实验尚无新版正式结果，不能移用standard或strict的34/40、RP2准确率或RP3蒸馏指标。
