## 二、工程回归：修了什么，没有修什么

### 2.1 根因与修复

原有布局层能够依据同栏原生文本行定位一条引句，但后续批量修复层又调用旧的连续页面/单元格字符串筛查。PDF多栏交错时，后者找不到连续引句，重新产生 `unbound_quote`，覆盖了前面的有效定位。

新增统一的 `native_evidence_binding_v2` 接口，同时供布局层与后续批量筛查使用。它每次针对**当前提案**重新定位，要求唯一原生路径，并逐个回读真实block/cell的起止字符，确认拼接内容与引句一致。满足条件时只移除 `unbound_quote`，其他类型、端点、未知单元和上游语义障碍仍保留。不复用过期“已通过”标志，不改写原文，也不制造连续页面偏移。

原生页面中实际存在的bbox可以作为定位元数据；这不等于给strict208的紧凑记忆补齐bbox。锁定来源文件实际有145条E1连续偏移记录、63条E2记录；顶层bbox均为空，但63条E2保留嵌套原生表格单元bbox，不能将其误称为源记录全无bbox，也不能声称全部记录具备bbox。既有缺失与现存位置字段均未修改。

### 2.2 同输入回放结果

对冻结的29页原始候选和10页句级候选，共39页484条，使用相同原始文档、候选及Schema比较修改前后完整链路：

- 修改前317条准入，修改后320条准入；没有新增拒绝。
- 全部484条最终语义载荷与修改前一致，输入没有被修改。
- 三条新增准入分别是：MP021第15页的吸入管漏气与噪声关系、同页管路连接后检查驱动对中、第20页的500小时或六个月润滑周期。
- 三条新增准入均已对照原生证据做AI初审，未发现这次修复新增的不正确放行；未经人类专家确认。

**仍存在的历史问题：** `MP021:p0015:H29:021` 的维护对象绑定不当，以及 `MP021:p0015:H29:023` 将“泵壳未变形”这类否定状态当作正向故障。二者在修复前后均被准入，本轮没有用候选ID黑名单隐藏它们。引句绑定正确不等于关系语义正确，接口修复也不能证明整个验证器已可靠。

相关9个测试文件共118项测试通过；原工作目录此前A3、P0/P1和受控标注工具的41项测试也通过，共159项。这里不是声称整个项目全量测试已运行。逐条变化和源文支持判断分别见结果目录的 `regression/` 与 `frequency/representation_judgments.json`。

## 四、准入到发布损失：主因不是候选遗漏

1698条自动证据准入记录中，1490条不在strict208图内；其中1118条已经进入standard1326图，余下372条未进入标准图。这些是同一批已生成、已经过自动证据准入的记录，不应重新记为LLM候选召回损失。

对372条记录按实际失败端点及术语组原因作互斥归类：

| 记录级原因 | 条数 |
| --- | ---: |
| 仅翻译置信/一致性准入不足 | 190 |
| 仅中文名称缺失或冲突 | 163 |
| 名称问题与置信问题同时存在 | 10 |
| 保护词未保留 | 5 |
| 未进入未解术语清单、但翻译状态仍不合格 | 4 |
| 合计 | 372 |

这里的“名称缺失或冲突”沿用可执行原因组，不代表163条都经过本轮人工消歧。另有286个未解术语组，是术语组数量，不是被阻塞记录数，二者不能相加。

`model_terminology_id_overridden_by_dictionary` 是词典覆盖模型ID的说明，不是拒绝原因。本轮统计只对 `graph_ready=false` 的端点归因，避免把该说明错误计作损失。该子集已经过关系Schema准入，因此这里新增的纯Schema失败为0；这不表示8003条完整审计池没有Schema问题。

在不放宽门槛的条件下，进一步检查了“只给失败端点复用标准图已有的类型+精确源文名称”。无论文档内还是跨文档唯一别名，能够一次补齐某条记录全部失败端点的预览数均为0。不能靠简单回填词典就承诺追回372条。

可保留的用途是来源可追溯的候选证据旁路，不是直接加入中文语义图，更不能直接转成安全操作建议。翻译、指代和关系语义仍需另外核验。本轮未修改术语阈值、Schema或发布结果。

## 五、30页源文检查：现象存在，但不能夸成全库频率

### 5.1 取样及判断口径

范围为15份构建文档、1934个物理页。每份文档按固定源文SHA优先级取2页，共30页，不根据候选输出挑页，不替换空白、目录、尺寸表或范围外页。MP008开发文档和所有外部文档未进入此次检查。

完整读过这30页的解析源文；对爆炸图、空白页、合并表格与关键多栏页另核对了6个PDF页面。MP016、MP019的意大利语/瑞典语判断为AI阅读与翻译，未经语言专家复核。F12、F22与此前39页审查重叠，因此不是全新盲测。

仅统计泵、关联驱动电机或明确可迁移的技术知识；排除一般管理、保修、回收处置、零件目录及不相关设备。“替代方案”指可替换的检查/处置动作，不把普通原因或品牌列表计入；“复合动作”要求顺序、依赖或联合前置条件，不把独立条目简单相加。

### 5.2 页面级初审结果

| 非互斥语义类型 | 出现页数/30 |
| --- | ---: |
| 条件、数值范围或执行时机 | 15 |
| 显式否定或禁止 | 10 |
| 替代检查/处置方案 | 3 |
| 有依赖的复合动作 | 8 |

至少一种目标语义出现于15页，分布在12份文档。这说明现象不是单篇文档特例，但不证明现有方法稳定失效。

每文档只取2页，且MP003占991页；文档等额样本比例不能直接作为全库页比例。结果文件保留了按文档页数加权的描述值，但不将其当作稳定总体频率，更不能解释成关系数量比例或召回率。页面原文、判断定义、真实引句地址和逐页说明均已保存。

### 5.3 表示能力小抽查

先固定17个非穷尽复杂语义靶点，再检查对应页面的主候选缓存、审计池、标准图和扩展图，并对135条原始主候选回放修复后的既有原生规则链。

- 8个靶点在该页主候选缓存中未见对应核心关系/动作。
- 4个部分保留：已有相关动作或端点，但缺少完整分支、组合绑定或有序参数。
- 5个已有字面保留，不能因没有独立条件字段而算作知识丢失。

例如：电机非驱动端跳机阈值已保存在端点中；“增加流量或换小泵”的OR已在动作文本中；“仅用于清液”和“运行前检查旋向”也已保留。另一些案例确有缺项，例如闭出口运行的5分钟/80°C联合限制、必要时更换或记录待维护的分支，以及两阶段烘干温度—时长顺序。

8个缓存核心缺失靶点中，T01涉及预测准确性，T02涉及共用传感器的法规例外。二者还需先明确Schema/任务范围，不能直接计入故障因果候选召回问题。其余也只证明本页主候选列表中未见相应项，**尚未证明模型全部原始响应字段或其他页面都没有生成该知识**。

既有规则链对17个靶点完整保留/准入4个。这不是方法召回率，更不是新方法胜过基线的证据：规则链输入仍是既有候选，本来就没有独立生成缺失核心关系的路径。它也没有解决所有引句/单元格绑定问题。

旧主记录中没有独立 `conditions/polarity/modality` 字段，不等于条件全部消失；条件可能在端点或原证据中。扩展图130条新增记录有额外原生上下文/模态元数据，也不能据此声称全部1456条已支持完整条件逻辑。

## 六、40条查询覆盖：不能用图内标签证明全文知识完备

固定40条受控查询仍是“已知故障范围+单一诊断角色”，不是开放式故障识别，也不是完整诊断卡。其自动参考关系来自strict208图及既定标签规则，不是独立源文穷尽标注。

34条查询的自动参考集合非空，6条为空：

| 查询 | 严格图参考 | 标准图相关自动标签匹配 | 独立扩展图相关自动标签匹配 |
| --- | ---: | ---: | ---: |
| 汽蚀—检查 CQ-F01-INS | 0 | 0 | 0 |
| 进气/失去灌注—症状 CQ-F02-SYM | 0 | 0 | 0 |
| 进气/失去灌注—检查 CQ-F02-INS | 0 | 0 | 0 |
| 水力堵塞—症状 CQ-F03-SYM | 0 | 0 | 0 |
| 电机电气驱动故障—症状 CQ-F08-SYM | 0 | 0 | 0 |
| 电机电气驱动故障—检查 CQ-F08-INS | 0 | 0 | 2 |

前5项在原始/审计候选中仍有自动标签匹配，但未达到准入/发布要求。不能据此断言原文没知识，也不能未经核验就称作验证误拒。最后1项说明扩展图有可进一步核验的电压、电流检查证据，不等于相关性或实际诊断有效性已被确认。

角色比较采用冻结RP2的“关系→角色”约定，未重写来源记录。strict208有7处角色字符串差别，其中2处只是上下文角色别名，真正语义角色差别为5处。另外8条查询的故障-角色粗标签匹配集合与冻结自动参考集合不同；参考集合比粗标签更细，不能把二者直接当作同一个集合。

对历史5种方法共200条输出逐条对齐，Ours_v6为34条回答、6条证据不足。但这不等于85%诊断准确率。即便在34条参考非空查询中，也有3条回答没有引用自动参考：

- CQ-F07-CAUSE：预算选择未包含参考，但回答引用了同故障的其他证据。
- CQ-F09-SYM、CQ-F09-MAINT：已选中参考，最终未引用，而引用了其他证据。

这些属于预算选择、验证/输出和参考边界的复核对象，不是已经证明的图谱缺知识，更不能不经源文检查直接判作错误回答。逐方法、逐查询的选择、引用、缺失参考ID已保存。

因此，本轮能分析“图内参考是否可用、是否被选中、是否被引用”，不能由这40条查询推算整个1934页语料的真实知识覆盖。

## 七、研究方向判断与下一道门槛

暂不把C类历史验证漏洞继续发展为学术主线。接口回归已修复；其余语义误放仍应做工程排查，但“补一条规则修一个例子”不能作为独立算法贡献。

A3也不能直接立项为普遍候选召回瓶颈。本轮确实看到了缓存中的缺失项，但原始响应全字段、任务范围与预算对照还没有闭合。17个选择靶点不是穷尽参考，无法给出可靠的全流程召回损失分解。

可保留一个较窄假设：**在原生证据约束下，维护动作的条件、替代分支与时序参数绑定是否会在抽取—准入—表示过程中丢失，并影响具体建议的适用性。**

下一轮只做验证，不先设计联合优化：

1. 对现有靶点先完成范围/Schema判定，明确哪些属于已有任务、哪些是新增要求。
2. 对缺失项检查完整原始响应及实际提示输入，区分未提供源文、候选列表遗漏、辅助字段已生成和验证拒绝。
3. 在模型可用服务器上，用相同页、相同候选上限、总token/调用预算比较现有链路、通用结构化提示/Schema约束、再读原文的通用恢复基线；不能让新方法单独多读一遍原文。
4. 分开评价原子关系保留、条件绑定、否定方向、替代/联合动作和数值时序参数。结果须能指回原生证据；不能用输出更多或全部拒绝来冒充改进。
5. 只有跨文档、多次运行仍有稳定缺口，并且通用方法不能解决，才设计专门机制；否则删除该机制。

本轮没有完成上述同预算模型对照，因此立项判断为“现象成立，方法必要性与创新性未证”，而不是“已经找到可写论文的新算法”。
