# RP1 独立复核与29页保留评价

日期：2026-10-03。执行顺序来自用户本轮要求：先完成独立复核，再冻结方法并评价29个保留页。

## 当前事实

仓库中的专家/独立人工评审字段仍为空。已有AI技术裁定、另一模型旧第二意见、运行正确性核验，都不能替代这项独立人工结果。本轮先把可执行材料准备齐全，不填写虚构评审，也不打开保留页正文。

复核包：[填写入口](../../results/experiments/research_point_1/independent_review_v1/README.md)。本轮仅增加一份独立复核包及读取式检查器，不增加新的优化臂。

## 最小复核工作

由具备相关专业背景、未生成现有AI标签的第二位评审执行；这不是运行时逐条审批。无需重新审阅全部8003条。

1. 先只看六页源文，独立列出应提取的核心知识和运行/背景/负向要求旁路；保存清单，再打开AI候选和参考表。空目标页也填写理由。
2. 对5个影响评价的口径问题作出说明：运行操作与维护动作、一般轴承知识的泵型范围、负向维护要求、直接/间接因果、许可条件与Otherwise。不确定项明确列出，不能强判负例。
3. 复核22条候选：10条本轮命中记录全纳入，再从每页其余候选中以固定哈希顺序抽2条，共12条对照。评审表不含原AI结论、放行状态或方法组名。该混合样本是开发诊断，不能由22条的正确率估计全体233或8003条。
4. 将独立清单与既有85项暂定参考逐项比较，标出有效、无效、需修改和未决，并保留新增/漏列知识。原79项开发分母及旧报告保持不变；新参考另存，不能事后回改开发指标。

一位真实的独立评审足以形成第二意见；不凭空要求多个专家或显著性检验。仍应说明评审资格、源文优先顺序和残余争议；如没有专家背景，则称独立技术复核，不称领域专家确认。

## 方法冻结

当前先封存候选方法的源码、schema和E1抽取提示哈希，状态为 `PENDING_INDEPENDENT_REVIEW`。这能防止后续无记录改动，但不是正式评价冻结。

真实复核完成后，记录争议如何处理及是否保持当前方法进入保留页评价；检查器核验表格完整、清单存在和依赖哈希。它只能核验交付完整性，不能自动证明评审者身份、专业性或语义正确性。若需要改方法，则在打开保留页前另存新版本；不覆盖现有实现。

正式冻结必须覆盖：E1提示与模型设置、旧机械筛查器、v4.1自动上下文/角色修复、clause_binding_v1、schema、29页清单，以及参考构建与匹配口径。旧冻结图和RP2/RP3教师不变。

## 保留页评价的最小设计

29页沿用2026-09-30清单及SHA256，不补齐MP017空表格层、不替换低信息页。覆盖15份构建文档：14个有表格页、15个无表格页；这是内部保留页，不是文档来源隔离或模型从未见过的外部测试。

控制工作量：正式新抽取只固定E1一种提示，每页一次，共29次；在同一批输出上比较原始、仅机械筛查、最终源文约束修复三组。E0/E1提示比较沿用已有开发实验，不在保留页再翻倍调用。模型与参数沿用已成功的qwen3.8-max配置，不静默换模型；每次原响应、失败和用量均保留，不自动重试。

先独立源页清单，再看抽取结果做准确性和一对一参考匹配。页面空目标、未决、图表不可判和跨页不完整分别记录。若确实无法评价，保留该页及原因，不用新页替换。仅有AI参考时只能报告模型参考一致性，正式准确率和召回率保持未完成。

联合报告：条件完整有效知识量、错误放行、正确知识误拒、页面完整匹配、准确率/召回率的明确分母、未决比例，以及实际调用数/失败/时延/token。原始组提供抽取器本身的质量；过滤/修复组提供准入收益及保留量代价。量级扩展在该评价之后决定。

发送29页到外部API的载荷须在正式冻结后具体生成并检查；当前没有生成或发送这些载荷，环境也未配置DASHSCOPE_API_KEY。已有六页的发送授权与响应缓存均原样保留。先完成复核再处理该执行条件，不在聊天或文件中写入密钥。
