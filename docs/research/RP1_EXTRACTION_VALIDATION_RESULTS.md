# RP1抽取改进与10页API验证结果

日期：2026-10-13。**已完成改进、固定页面、API重新抽取和源文AI抽查；75%的应用成功率目标未达到。** 本批数据没有发布为最终应用图谱。

## 核心结果

| 指标 | 结果 | 解释 |
|---|---:|---|
| 固定目标页 / 完整响应页 | 10 / 10 | 1页故障表、4页维护、5页正文 |
| 全部收到的输出记录 | **224** | 保留不合约、背景、未决和被拒记录 |
| 程序通过记录 | **129 / 224，57.6%** | 结构、类型和原生证据地址检查，不等于真实可用 |
| 程序通过记录的去重关系 | **129** | 中文类型/名称/关系/正负极性精确去重，不是129条已证实新增知识 |
| 固定AI抽查 | **60** | 从全部224条按固定SHA优先序抽取，包括程序未通过者 |
| 源文与条件符合要求 S / 有缺陷 E / 未决 U | **25 / 30 / 5** | 单AI非盲判断，U仍在分母 |
| 抽查中同时满足源文要求并通过程序 | **23 / 60，38.3%** | 本样本的联合合格比例，不能称224条全量准确率 |
| 抽查中程序放行但有源文/条件缺陷 | **16** | 自动门控仍不能替代语义核对 |
| 抽查中有源文支持但被程序拒绝 | **2** | 原文省略号/连字断行等证据绑定问题 |
| 调用前源文检查清单 | **65项** | 26项表达完整、39项部分表达；不是正式召回率 |

224条中13条无法按约定字段解析关系键，仍计入总分母；其余211条可解析记录对应210种精确关系键，有1次重复。不能把多个不合约记录合并为一个“重复关系”而缩小分母。129条程序通过记录的真实语义质量没有全部核定，不能都写成合格应用知识。

## 实际改进了什么

抽取从平铺三元组改为**共享源文上下文＋具体角色关系**：

- 上下文保存型号/章节/程序或表格分支、原生单元ID、引用和条件。
- 每条关系单独保存两端源文、中文名称、语义类型、极性、模态和对应上下文。
- 本地程序继承声明的条件，回读原始block/cell字符和bbox；前页只作上下文，关系必须包含目标页证据。
- 提示明确要求措施针对故障后果、保留禁止/无需维护要求、不同原因分支独立绑定，不把状态、工具、材料强行当作部件或标准。

模型与参数为qwen3.8-max、temperature=0、enable_thinking=false、JSON输出、max_tokens=16384。提示与页面在调用前固定，模型没有看到本轮65项检查清单或预设语义标签。

这是角色、条件与证据的联合表示试验。上下文共享可以减少重复和遗漏，但模型给出一个context_id并不证明条件继承正确。当前结果不足以宣称整体算法改善，历史8003条与本批数据的模型、输入、页面分布和门控实现也不同，不能据14%或18%的旧通过率计算因果增益。

## 为什么未达到75%

1. **自由生成原文与地址仍不可靠。** 例如P07:011写出含省略号的“原文表述”，部分温度引用把原生特殊字符改写；P10维护步骤遇到断行连字。还有头实体地址指向只含温度而不含泵的单元。
2. **类型和关系仍被强行套用。** 检查管路用mitigated_by+InspectionAction；泵型号变成contains的Component；材料变成Standard；正常功率需求变成Risk或FailureMechanism。
3. **共享条件仍会错绑。** P02:011将碳环未固定条件附到波纹管紧时的装配；P02:014把启动后检查的时序附到15分钟就位过程；P03:004把堵塞处理条件附到定期阀检查。
4. **关键共用前提没有建立连接。** MP021 p6把装拆程序和开泵前排压/锁定警告分成上下文，相关动作未继承后者。这里的E说明条件完整性不足，不表示动作本身在源页不存在；原子动作也不被要求复制整套维修规程。
5. **复杂JSON在长输出中出现格式漂移。** MP021 p6后12条记录的键名、ID和值带前导空格，另有一个字段不完整的记录。它们没有被静默清理后当作模型合格输出。

已有明确成功案例：FS型号限定和F型号跳过指令得到保留，多条拆卸动作具有正确步骤号；Ø215/265叶轮装配条件被保留；外部振动超过7mm/s的风险分支和部分负向拆卸要求正确表达。它们是局部可复查成果，不抵消整体失败。

65项检查清单在调用前仅依据源文形成，粒度包含单条关系和多动作要求，并不穷尽所有知识。26项“表达完整”表示对应内容在返回记录集合中出现，**不表示所有对应三元组通过门控或满足应用质量**。39项部分表达显示本轮主要不是完全没提及，而是角色、条件或表示完整性不足；不能将26/65写成正式召回率。

## 运行与校验说明

10页共有11次网络请求：首次10次中MP021 p6在180秒超时，保留失败记录，对该页使用完全相同的冻结载荷显式重试一次，等待上限600秒。没有内容不利而重抽，没有替换目标页。收到的10份成功响应记录205641 tokens，其中输入135309、输出70332；第一次超时可能已计费或在服务端完成，其输出未知，不能当作0条或声称精确总费用。

初始本地编译器错误地要求两端表述必须在一个原文块内，违背多单元引用契约。前几页返回后修正为真实连续原生路径，并支持解析器把同一正文同时表示为table和block的情况。修正前完整224条决定保存于日志，程序通过79条，修正后129条；**这50条是工程读取修正，不是模型新增知识或语义质量提升**。修正发生在响应出现之后，已明确记录，不伪称全部代码调用前冻结。提示、载荷、页面、检查清单和75%目标没有改变。

10项针对条件继承、多块原文、跨度/引用、跨页来源及不合约输出保留的测试通过。独立重建10页选择、10份原始响应、224条本地决定、1318个原生位置、60条固定样本及65项检查清单汇总通过。旧图源文件哈希保持不变；本轮没有调用或修改RP2/RP3教师。

## 结论与直接后续

**本次完成了真实API验证，并确认当前方法仍不达标。** 最终应用图谱不能从129条程序放行记录中直接扩充。

下一步应把模型自由书写的内容进一步收敛为“选择原生单元和端点跨度、在明确允许的类型/关系中选择、指定每个局部条件属于哪条分支”；原文由程序读取，公共型号/章节条件和局部if/when条件分别处理。先复用本次224条响应修正接口与条件表示，使用这10页开发后再验证时须另选目标页，不能把同页改进冒充未见页结果。继续保持一个最终应用图谱目标，不增加多个可选应用图。
