# 研究点二v3最终化与来源留出外部评价协议

更新日期：2026-08-03

## 1. 不可交换的执行顺序

```text
开发集v3主实验与消融
→ 三方法交错重复时延
→ 三方法双提示词Silver语义Judge
→ 生成冻结清单并提交Git
→ MP010–MP013一次性外部抽取
→ 隔离外部Silver基准与索引
→ 冻结三方法外部GraphRAG评价
→ 完整报告，不回流调参
```

外部流程会检查冻结清单已经存在于Git `HEAD`，并逐文件复核冻结配置、检索代码、生成代码、开发指标、时延结果和Judge结果的SHA256。任何冻结文件变化都会终止外部评价。

## 2. 交错重复时延

冻结方法为 `B1_dense_k4`、`B4_metapath_k3` 和 `Ours_k3`。40个查询各重复5次，每轮根据“重复编号＋查询编号”进行Latin轮换，使每种方法均衡出现在第1、第2和第3执行位置，共600次真实本地7B推理。每种方法开始前执行2次不计入统计的预热。

在线时延包含BGE查询编码与检索、精确提示词预算拟合、Tokenization和确定性生成。模型加载与离线索引构建不计入热启动在线时延。逐调用结果实时追加到JSONL，中断后重复同一命令只补未完成组合。

## 3. 双提示词Silver语义Judge

评价开发集三方法共120条回答。Judge A进行严格回答—引用原文蕴含判断；Judge B主动寻找对象偷换、方向错误、条件删除、确定性扩大、证据拼接和摘要新增事实。

两个角色均使用 `qwen3.7-max`、temperature=0，但提示词角色独立。只有两路均判 `supported`，且两路给出的连续短引文都能回查到被引用原文，才记为严格支持。

该实验是同一模型的双提示词Silver审计，不是两个独立模型，更不是人工专家Gold评价。API Key仅通过隐藏输入进入环境变量，不写入文件和命令历史。预计82次API调用带缓存，可中断恢复。

## 4. 冻结门

`freeze_rp2_v3_protocol.py`仅在以下条件满足时生成冻结文件：

- 40个查询、3种方法、每种至少200条时延样本；
- 120条回答的完整双提示词语义审计；
- 外部v3结果尚不存在；
- 开发配置和必需结果完整。

冻结操作不因结果好坏改变方法。冻结文件必须与时延和Judge结果一起提交Git，之后才可进入外部评价。

## 5. MP010–MP013外部评价

MP010–MP013共103个物理页，确定性排除后94个抽取页。它们早期已经完成机械式页面解析，因此对完整v3只称为“来源留出外部评价”，不称为完全未接触盲测。

外部处理继续使用冻结的 `marine_pump_full_corpus_prompt_v4`、Schema、术语表和双重自动裁决。外部Silver：

- 不进入 `KG_v1_validated`或主图索引；
- 不修改K、图权重、来源奖励、提示词或回答长度；
- 使用隔离的外部候选语料和隔离BGE索引；
- 查询从整个外部候选语料检索，不构造含正例的小候选池；
- 结果无论好坏只报告一次，不回流开发。

主置信策略会为所有 `held_out_test` 记录保留 `held_out_test_not_primary_graph_eligible` 否决项，因此外部记录不得复用主图的 `silver_candidate` 标签。隔离外部流程使用独立的 `external_silver_candidate`：只有E1/E2原文证据有效、关系类型合法、关系被直接蕴含、最终置信度达到0.8且双重裁决未拒绝时才发布；其主决策和 `eligible_for_chinese_graph=false` 保持不变。

若冻结后的外部基础设施缺陷导致尚未产生任何有效外部结果，只允许通过版本化附录修复外部标签适配、空语料检查或隔离索引代码。附录必须证明检索参数、生成契约、模型和开发结果未变化，记录缺陷发生时外部候选为0，并在恢复外部评价前提交Git。不得直接改写原冻结清单。

四份外部文档都属于MAIB来源族，因此外部集不能评价来源族多样性增益；外部评价只解释检索迁移、回答Silver效用、语义支持和时延。

## 6. 结果命名边界

所有自动抽取三元组、外部查询、相关证据、回答、双提示词Judge和外部结果均为Silver，不能称为Gold。双提示词一致性也不能改写为人工专家准确率。
