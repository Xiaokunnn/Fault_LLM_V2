# 船舶机舱泵系大语言模型知识增强故障辅助诊断三研究点主规划

版本：V2.0  
冻结日期：2026-08-01  
性质：后续研究、代码目录、实验命名和论文写作的统一依据  
依据：`船舶机舱泵系方向下的硕士论文三研究点重规划建议.pdf`、当前 `KG_v1` 数据资产及服务器模型条件

## 1. 论文总主题与不可偏离边界

建议论文总题目为：

> 面向船舶机舱泵系的大语言模型知识增强故障辅助诊断方法研究

论文研究的不是单独的数据库构图，也不是脱离大模型的图搜索，而是解决以下连续问题：

1. 如何利用大语言模型从多源技术文档中生产可追溯、可审计的领域知识；
2. 如何利用知识图谱和向量模型为大语言模型选择高质量、低冗余、多来源的诊断证据，并改善最终回答；
3. 如何把 GraphRAG 教师的证据使用和诊断能力蒸馏到本地 7B 模型，在少检索或按需检索条件下实现更低成本、风险受控的推理。

统一主线为：

```text
多源泵系技术文档
→ 大模型抽取与审计型Silver知识图谱
→ 向量召回 + 图谱约束检索 + 7B证据生成
→ GraphRAG教师监督
→ 7B证据蒸馏/知识内化 + 选择性回退
```

以下原则不可改变：

- 研究对象始终是船舶机舱泵系，不回到通用轴承或通用机械图谱。
- 三个研究点全部保留；当前优先完成研究点一、二，不表示删除研究点三。
- 所有自动或半自动三元组、查询、相关性标签、教师回答和蒸馏样本均称为 Silver，绝不称为 Gold。
- `Edge_Fault_LLM` 仅作为只读算法原型，旧轴承数据和旧结论不得进入新论文主实验。
- RTX 5880 48GB 服务器是主要实验平台；不强制使用树莓派或 RK3588。低资源结论通过统一显存、量化、并发和时延协议验证。
- MP008仅用于开发；MP009–MP013不进入主图谱或回流调参。MP010–MP013是在结构检索v1冻结后解析，但早于加入向量模型和7B生成的正式v2协议，因此只能称为“来源留出外部测试”，不能称为对v2完全未接触的严格盲测。

## 2. 三研究点之间的逻辑关系

| 研究点 | 核心角色 | 大模型的作用 | 主要输出 |
|---|---|---|---|
| 研究点一 | 可信知识生产 | `qwen3.7-max`完成受本体约束的抽取与语义裁决 | 审计图、中文发布图、来源与证据治理报告 |
| 研究点二 | GraphRAG知识使用 | 向量模型负责语义召回，本地7B负责证据约束回答 | 冻结检索器、EvidenceBench、带引用诊断回答 |
| 研究点三 | 能力内化与风险控制 | GraphRAG作为教师，本地7B经QLoRA/蒸馏成为少检索学生 | 蒸馏模型、选择性回退器、成本—质量—风险曲线 |

研究点一解决“知识是否可信”，研究点二解决“模型如何检索并使用知识”，研究点三解决“如何减少在线检索且控制错误”。

## 3. 研究点一：大模型驱动的审计型 Silver 知识图谱构建与质量治理

### 3.1 建议名称

> 面向船舶机舱泵系故障辅助诊断的大模型审计型 Silver 知识图谱构建与质量治理方法

### 3.2 核心问题

如何约束大语言模型，使其从船级社规范、厂商手册、安装指南和事故报告中抽取具有原文蕴含、页级定位、稳定中文语义和来源家族信息的泵系故障知识，并将不可靠结果自动隔离？

研究点一不是“调用模型抽三元组”，而是研究大模型知识生产中的质量治理。模型输出候选主张 (c)，系统联合验证证据对齐 (E(c))、本体合法性 (S(c))、关系蕴含 (M(c))、来源完整性 (P(c)) 和中文术语发布状态 (T(c))：

\[
G(c)=\mathbb I[E(c)=1]\mathbb I[S(c)=1]\mathbb I[M(c)=1]\mathbb I[P(c)=1].
\]

其中 (G(c)=1) 只表示证据合格 Silver；进入中文发布图还需满足 (T(c)=1)。因此形成：

\[
\mathcal G_{raw}\supseteq\mathcal G_{silver}\supseteq\mathcal G_{zh-release}.
\]

对同一语义主张 (c)，来源支持不能按同厂商文档数量机械累加，而按来源族 (f) 聚合：

\[
I_{fam}(c)=1-\prod_{f\in F(c)}(1-w_f),
\]

同一来源族内部复制不会改变 (F(c))，从而避免“一个厂商多份手册”造成虚假独立佐证。

### 3.3 方法模块

1. 泵系故障本体与关系 Domain/Range 约束；
2. `qwen3.7-max` 冻结提示词下的候选主张抽取；
3. E1连续原文、E2表格同行/同行组、E3重建证据分级；
4. 关系方向、否定、条件、适用泵型和故障类别校验；
5. Silver / Quarantine / Reject三级审计；
6. 中文规范实体与原语言surface双层保存；
7. 文档、页码、bbox、URL、文档哈希和页面哈希溯源；
8. 来源家族聚合、复制不变性和双图发布机制。

### 3.4 当前完成度

- 15份构建文档、1934个物理页完成主数据线构建；1889页进入全量抽取。
- 共8003条审计记录；1698条证据合格Silver、881条隔离、5424条拒绝。
- 形成1650项去重语义主张、2613个实体和10个构建来源家族。
- 十类故障的症状、原因/机理、检查和维护证据覆盖达到10/10。
- `KG_v1_raw` 与 `KG_v1_validated` 已形成；原文与中文规范语义分层保存。
- CQ v1、结构约束报告、来源族封顶指数及×1/×2/×4/×8复制压力实验已完成。
- 固定20页 `qwen3.7-max` 真实API提示词对照已完成：Ours产出148条严格Silver，B0/B1/B2/B3分别为0/50/31/32条；该结果衡量结构与证据产出，不是事实准确率。

### 3.5 尚需完成

1. 冻结内部构图质量、来源族实验、结构约束和真实API对照表格；
2. 为研究点二另建不降低中文发布门槛的`KG_rp2_release_v1`，解决当前208条发布图规模偏小问题；
3. 等研究点二GraphRAG v2全部冻结后，再在MP010–MP013上运行同一抽取与治理流程，报告跨来源外部迁移；
4. 明确限制：没有领域专家全量审核，所有质量结论限定为可追溯Silver一致性，而非临床式或工程安全准确率。

### 3.6 主要实验

- 提示词/约束增量对照：B0自由抽取、B1本体约束、B2证据对齐、B3方向与范围、Ours完整治理；
- 关键模块消融：去证据门、去关系门、去术语治理、去来源家族治理；
- 来源族复制压力：×1/×2/×4/×8；
- 外部来源迁移：MP010–MP013；
- 指标：结构合法率、原文支持率、页级落地率、provenance完整率、中文发布率、隔离率、来源家族覆盖和CQ可回答率。

## 4. 研究点二：面向本地7B大模型的证据约束 GraphRAG 检索与生成优化

### 4.1 建议名称

> 面向船舶机舱泵系故障辅助诊断的来源感知预算约束 GraphRAG 方法

### 4.2 核心问题

给定泵系故障问题，如何联合向量语义召回、图谱关系约束、来源族多样性和上下文预算，为本地7B模型选择最相关、最可信且低冗余的证据，并提高最终诊断回答的证据忠实性？

候选证据 (e) 的检索相关性由向量相似度、图结构一致性、证据置信和来源因素共同决定：

\[
r(e,q)=\alpha s_{dense}(e,q)+\beta s_{graph}(e,q)+\gamma c(e).
\]

在候选集 (C_q) 中选择证据子集 (S)：

\[
\max_{S\subseteq C_q}
\sum_{e\in S}r(e,q)
+\lambda |F(S)|
-\mu\sum_{e_i,e_j\in S}overlap(e_i,e_j),
\]

满足：

\[
|S|\le K,\quad tokens(S)\le B_t,\quad |S_f|\le K_f,\quad latency(q)\le B_l.
\]

优化目标不是单纯减少Token，而是在质量硬约束下取得来源多样、低冗余的证据，并降低检索与7B生成的端到端成本。

### 4.3 正式系统流程

```text
中文故障问题
→ 向量模型编码查询
→ 实体/Claim/Evidence向量召回
→ 图谱锚点与诊断关系角色门控
→ 固定跳数、旧自适应剪枝或元路径增量扩展
→ 来源族感知预算选择与冗余抑制
→ 证据原文、页码、URL确定性序列化
→ 冻结本地7B模型生成结构化诊断卡和自然语言解释
```

向量模型与7B模型必须固定版本。所有检索方法使用同一个7B、同一回答提示词、同一解码参数，确保答案差异来自检索而不是生成器变化。

### 4.4 当前实现的正确定位

当前已完成的词法倒排、固定两跳、旧自适应剪枝、元路径门控、来源族预算和K=4 Pareto实验，是研究点二的“结构检索先导实验”，不是最终GraphRAG实验。当前 `marine_pump_rp2_budget_retrieval_v1@1.0.0` 继续冻结保存，用于复现实验历史，但论文正式协议升级为 v2 后必须加入：

- 服务器现有向量化模型；
- 本地7B回答生成；
- 端到端答案与证据忠实性评价。

不得把现有字符二元词法结果直接表述成完整GraphRAG结论。

### 4.5 正式对照组

| 编号 | 方法 | 检索 | 7B生成 |
|---|---|---|---|
| B0 | Closed-book LLM | 无外部证据 | 是 |
| B1 | Dense RAG | 向量Top-K文本/证据 | 是 |
| B2 | Fixed-hop GraphRAG | 向量锚点+固定两跳 | 是 |
| B3 | Adaptive GraphRAG | 向量锚点+旧自适应能量剪枝 | 是 |
| B4 | Metapath GraphRAG | 向量锚点+关系角色/元路径 | 是 |
| Ours | Source-aware Budgeted GraphRAG | 向量+元路径+来源族+冗余抑制+预算 | 是 |

### 4.6 评价指标

检索层：Recall@K、MRR、nDCG、故障四角色覆盖、来源族覆盖、精确Claim冗余、访问节点/边、评分候选数和p50/p95时延。

生成层：答案关键点覆盖、证据忠实性、引用正确率、无证据断言率、拒答正确率、首Token时延、总时延、输入/输出Token和峰值显存。

主结论必须同时报告检索层和生成层。大模型Judge只能作为补充，不能代替证据ID和原文蕴含评价。

### 4.7 下一步执行顺序

1. 先冻结RP2专用中文Silver检索图及其规模、可回答性和哈希；
2. 登记服务器向量模型、7B模型、推理框架、精度、显存与版本哈希；
3. 为实体、Claim和Evidence建立离线向量索引，并实现查询向量入口；
4. 将现有固定两跳、旧自适应剪枝、元路径和Ours接到同一Dense候选集；
5. 构造统一7B证据回答模板，强制逐条引用证据ID，不允许补写未检索事实；
6. 先在MP008/构建集CQ开发，并从完整检索图搜索；当前保证含正例的64条候选池只作先导联调；
7. 完成B0–B4–Ours检索层与端到端生成层实验并冻结GraphRAG v2；
8. 冻结后才生成MP010–MP013外部Silver并做一次来源留出迁移评价；若投稿必须声称严格盲测，应另登记1–2份此前从未接触的新来源；

## 5. 研究点三：GraphRAG教师到本地7B的证据蒸馏与选择性回退

### 5.1 建议名称

> 面向船舶机舱泵系故障辅助诊断的证据知识蒸馏与风险受控推理方法

### 5.2 核心问题

如何把研究点二中“向量召回+图谱证据选择+结构化诊断”的教师能力内化到本地7B模型，使其在无需每次访问完整图谱的情况下保持诊断质量，并在证据不足或分布偏移时主动回退GraphRAG？

本研究不要求另购边缘板。以服务器上的7B基础模型为学生，通过QLoRA和4/8bit量化模拟资源受限部署。教师为冻结的Ours GraphRAG系统；必要时仅用 `qwen3.7-max` 生成或复核少量高价值Silver教师样本。

蒸馏目标由结构化字段、证据选择和回答联合组成：

\[
\mathcal L=\mathcal L_{answer}
+\lambda_1\mathcal L_{evidence}
+\lambda_2\mathcal L_{action}
+\lambda_3\mathcal L_{consistency}.
\]

学生推理时计算风险分数 (u(x))，形成三级路由：

\[
\pi(x)=
\begin{cases}
student, & u(x)<\tau_1,\\
GraphRAG, & \tau_1\le u(x)<\tau_2,\\
abstain/review, & u(x)\ge\tau_2.
\end{cases}
\]

### 5.3 主要实验

- Base-7B closed-book；
- 普通Silver SFT；
- 最终答案蒸馏；
- 证据ID+检查维护动作联合蒸馏；
- Ours：联合蒸馏+量化+选择性GraphRAG回退。

指标包括诊断关键点覆盖、证据忠实性、无依据断言率、图谱调用率、平均/p95总时延、峰值显存、风险—覆盖率曲线、期望校准误差和外部来源偏移下的性能下降。

### 5.4 启动门槛

研究点三只有在以下条件满足后启动正式训练：研究点二向量索引、Ours参数、7B提示词、教师回答格式和训练/校准/测试划分全部冻结；MP009–MP013不得进入学生训练。

## 7. 当前阶段的统一结论

1. 研究点一的内部方法与实验闭环已完成，剩余与研究点二协议共享的外部来源评价及论文定稿。
2. 研究点二只完成了不含向量模型和7B生成器的结构检索先导实验，不能称为完整GraphRAG完成。
3. 研究点二现在的第一优先级不是继续微调字符词法K值，而是接入服务器向量模型与7B模型。
4. 研究点三尚未正式启动；其训练数据必须来自冻结后的研究点二GraphRAG教师。
5. 两个近期投稿可以分别围绕研究点一和研究点二，但研究点二投稿必须补全向量召回和7B端到端生成实验。
6. MP010–MP013只可表述为来源留出外部集；如果正式v2需要“完全未接触盲测”，必须另加新文档并在下载前冻结全部协议。
7. 研究点一的1698条证据Silver与208条中文发布Silver必须分开报告；RP2正式实验前需要另行冻结规模更充分的中文Silver检索图。
