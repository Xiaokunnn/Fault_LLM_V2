# 船舶机舱泵系大语言模型知识增强故障辅助诊断三研究点主规划

版本：V4.0（研究点三定型版）

更新日期：2026-08-13

事实主线：研究点一 ICSMD 2026 终稿、研究点二 D2AI/ICDM 2026 终稿及其冻结实验资产

## 1. 总体问题

建议论文总题目为：

> 面向船舶机舱泵系的大语言模型知识增强与轻量化故障辅助诊断方法研究

三个研究点依次回答：

1. 没有逐条人工审核时，如何从异构技术文档自动生产证据可定位、来源可追溯、失败可审计的知识记录？
2. 在固定本地模型和证据预算下，如何选择少量任务匹配的证据，提高引用支持并降低模型推理负担？
3. 如何把证据选择、支持判别、欠填/拒答和成本决策压缩到轻量学生，并在边缘端保持证据契约和可控回退？

统一逻辑为：

```text
自动证据契约门控的知识生产
→ 预算约束的证据使用
→ 证据契约保持的决策蒸馏与边缘执行
```

本文不再使用 `Silver` 作为研究点名称或核心创新概念。历史论文、冻结配置和物理目录中的 `silver_*` 名称为复现标识，保持不变。当前叙述统一使用“候选记录、自动证据合格记录、隔离记录、拒绝记录、教师生成监督”。自动合格只代表通过冻结的可执行证据契约，不代表专家事实确认。

## 2. 研究点一：无需逐条人工审批的证据可追溯知识图谱构建

### 2.1 论文主线

英文主稿：`papers/ICSMD_2026/RP1_ICSMD2026_English_Final.tex`

中文主稿：`papers/ICSMD_2026/RP1_ICSMD2026_中文正式稿_v5.tex`

建议名称：

> 面向船舶机舱泵系技术文档的自动证据质量门控与可追溯知识图谱构建方法

### 2.2 核心贡献

- 将规范化Claim与每一次页面级Evidence Assertion分离，语义去重不覆盖多页、多文档证据；
- 以Schema/Domain-Range和方向、E1连续原文或E2表格定位、关系支持、来源谱系、构建集边界与非推断条件形成可执行准入契约；
- 全审计图保留全部候选与失败原因，中文应用图按术语完备性形成严格、保守、标准层；
- 来源族封顶避免同一厂商重复资料被误当作多份独立佐证；
- 通过全候选重定位、受控规则破坏、术语层敏感性、来源留出和同族复制压力评价已声明规则。

### 2.3 已完成事实

- 15份构建文档、1934个物理页；1889页进入抽取。
- 8071个原始候选归一化为8003条审计记录：1698条自动证据合格、881条隔离、5424条拒绝。
- 自动证据合格记录对应1650项唯一三元组和2613个源语言实体；其中E1为1550条、E2为148条。
- 标准中文应用层包含1326条证据记录、1281项Claim、2022个中文实体；严格层为208条。
- 1698条合格记录通过重新定位与来源检查；13729个受控规则破坏全部触发至少一道门。这只验证编码契约行为。
- 当前没有专家事实标签，不能报告三元组事实Precision/Recall/F1、诊断准确率或工程安全性。

### 2.4 对后续的接口

研究点一向研究点二、三提供的不是“绝对真值”，而是具备稳定ID、原文、物理页、URL、哈希、适用范围和门控轨迹的可审计知识记录；定位字段按上游实际存在情况原样继承，当前strict208只有字符偏移而没有bbox，必须显式保留这一缺失状态。

### 2.5 硕士论文研究点审查结论与补强

**结论：达标。** 研究点一具备独立问题、独立方法、全语料实验、失败分析和小论文闭环。硕士正文必须把创新固定在“无需逐条人工批准的自动证据准入与审计机制”，而不是泛化成“LLM自动抽取”或“自动得到事实真值”。

正文增加三个契约内命题，以补充理论深度：

1. **溯源闭包。** 任一进入应用图的Evidence Assertion都能沿稳定ID恢复到不可变原文、物理页、URL、哈希和源记录实际具备的定位字段；任一必需字段恢复失败均使其不能进入应用图，源记录不存在的bbox只能显式标记缺失。
2. **合取门控的单调拒绝性。** 准入函数是若干必要条件的合取；新增必要门不可能把原拒绝记录变为合格记录，受控破坏任一必要条件不能提高准入状态。
3. **来源族内复制不变性。** 在来源族封顶下，对同一来源族内证据进行任意复制，不改变该Claim的跨来源族支持分数。

无专家事实标签时，研究点一仍可成立，但必须持续放弃事实Precision/Recall/F1和诊断正确率主张。若后续条件允许，可做小规模、分层、盲法专家抽检作为外部评价；它不参与逐条准入，也不改变“无需逐条人工审批”的方法定义。

## 3. 研究点二：预算约束型混合证据选择与核验负载控制

### 3.1 论文主线

英文主稿：`papers/D2AI_ICDM_2026/RP2_D2AI2026_English_Final_v1.tex`

中文主稿：`papers/D2AI_ICDM_2026/RP2_D2AI2026_中文初稿_v6.tex`

建议名称：

> 面向本地大语言模型的预算约束型混合证据选择与泵系故障核验负载控制方法

### 3.2 问题与边界

查询为 `q=(x,f,r)`：自然语言问题、预先给定的候选故障范围、预先给定的症状/原因机理/检查/维护角色。研究点二不解决开放式故障识别。

BGE-M3先返回top-32证据；以top-8端点为锚点进行一跳传播，再结合角色、故障范围、证据先验、来源新颖性和主动欠填，最多选择3条证据。Qwen2.5-7B只输出两阶段0/1支持掩码，确定性渲染器形成带证据ID的原子建议或证据不足拒答。

### 3.3 已完成事实

- 冻结底座为208条严格中文证据、14份文档、10个来源族；40条受控查询含34条可回答和6条不可回答。
- Full K3相对Dense K3：Recall 0.218→0.431，NDCG 0.406→0.822，Citation F1 0.259→0.426。
- 平均提示长度1066.7→634.7 Token，模型调用2.95→1.80，平均端到端时延839.4→531.2 ms。
- Full完成34/34作答和6/6拒答。同模型双提示自动审计中，91.0%的原子建议与引用片段严格一致，88.2%的已回答样本全部原子点获支持；这些不是专家正确率。
- Full与Full-NoGraph的平均差异很小且不显著；一跳图传播应解释为尾部召回补充，不是全部增益来源。

### 3.4 对研究点三的教师接口

可传递五类轨迹：候选及分数组成、预算排序与欠填、两阶段支持掩码、证据ID与来源谱系、逐样本Token/调用/时延成本。确定性渲染器本身无需蒸馏。

当前输出只是单角色原子回答，不是完整诊断卡；研究点三开始前须先定义诊断卡schema并由冻结教师生成联合字段。

### 3.5 硕士论文研究点审查结论与补强

**结论：有条件达标。** 研究点二已经形成独立的预算选择方法、固定7B支持核验协议、等预算对照、拒答行为和质量—时延联合评价；但其边界是已知故障范围与诊断角色后的证据子系统，不是开放式故障识别。完整方法与去图方法的平均差异不显著，因此一跳传播只能作为尾部召回信号，不能把“图推理”写成主要贡献。

硕士正文采用以下优化：

- 将主贡献写成“任务/故障可行域中的预算证据选择、主动欠填与核验负载控制”，向量和一跳图是候选信号；
- 将“34条可回答问题均得到有效回答”改为“对34个预指定可回答查询均输出了证据链接建议”，不把行为覆盖等同于正确诊断；
- 将“高可信图谱”改为“自动证据合格且可追溯的证据底座”；
- 以
  \[
  F(S;q)=\sum_{e\in S}b(e,q)+\lambda\lvert\{\phi(e):e\in S\}\rvert,
  \quad S\subseteq\mathcal E_{f,r},\quad |S|\le K
  \]
  说明约束选择。对非负基础效用，来源覆盖项是单调次模函数，可讨论标准贪心的近似边界；主动欠填仅发生在可行候选不足或显式停止项胜出时。

可选增强实验按优先级为：208/620/1326只读底座的规模—时延曲线、按文档/来源族分组的泛化评价、独立专家支持性抽检。它们不能改写已经冻结的RP2 v6教师结果。

## 4. 研究点三：证据控制策略蒸馏与选择性边缘推理

### 4.1 定型名称与一句话说明

> 面向边缘端泵系故障辅助诊断的证据控制策略蒸馏与选择性回退方法

研究点三训练一个可由LLM或确定性编排器调用的**轻量证据控制器**（Lightweight Evidence Controller，LEC）：它接收“问题、已知故障范围、诊断角色和本地候选可用性”，返回证据ID、直接支持判定、预算停止点以及“本地回答/完整教师回退/拒答”动作；LLM只消费该工具返回的证据包，不能自行伪造证据。

教师能力的转移对象不是整段回复文本，而是四类可评价决策：证据排序、直接支持判别、字段欠填/停止和代价敏感路由。LEC是创新主体；LLM是证据工具的调用者和可选语言界面；确定性组合器负责权威诊断辅助卡。

### 4.2 教师、学生与冻结边界

教师不是单一LLM，而是研究点二冻结系统：BGE-M3宽召回、一跳候选信号、预算选择、Qwen2.5-7B两阶段支持核验、主动欠填/拒答和确定性渲染。

主教师固定为RP2 v6已经复现的208条严格中文证据底座，并建立 `TeacherGraph_RP3_v1` 哈希清单。620条和1326条底座只用于主方法与阈值冻结后的 `TierShift-620`、`TierShift-1326` 容量和迁移压力测试；除非在其上完整重建索引、重放教师并另行冻结，否则不得替换主教师或并入208主结果。

当前RP2配置声明的BGE索引目录在本机缺失。因此当前阶段只生成冻结、重建与重放代码；教师清单必须失败关闭，不能声称已经完成冻结或精确重放。

学生主体是参数量目标小于50M的LEC，而非另一个会背答案的3B生成模型。建议主配置采用冻结的小型中文编码器加轻量候选交互层和四个输出头，部署以ONNX INT8为主。Qwen2.5-3B INT4可作为边缘对话壳/工具调用者，1.5B和7B只作容量边界；任何自然语言解释不得新增证据包之外的原子诊断主张。

### 4.3 有界证据记忆与LLM工具接口

离线把教师证据编译成按 `fault_id × role` 分桶的只读记忆。每项保存稳定证据ID、Claim ID、量化候选键、关系/角色/故障范围、来源族、置信区间以及来源记录的地址与哈希。原文、物理页、字符偏移、URL和哈希由ID在只读表中确定性恢复；当前strict208源记录的bbox字段全部缺失，必须显式标记缺失，不能声称已恢复bbox。

在线工具契约为：

```text
select_pump_evidence(question, fault_id, role, available_evidence_ids?, max_points<=3)
  -> selected_evidence_ids
  -> controller_rank + support_probability + support_verdict
  -> field_state: supported | insufficient | conflict
  -> stop_reason
  -> action: answer | fallback | abstain
  -> controller_version + memory_hash
```

这是面向LLM/编排器的高层接口。候选列表、可用性掩码、候选签名以及模型、记忆和校准哈希由服务端冻结注册表注入，不允许由LLM自由填写；底层全字段请求只用于重放、审计和故障定位。在线Route头是由教师实际纠错收益与三类动作代价监督得到的三分类策略，运行时再施加只能升级到更保守动作的单调防护；“期望代价最小化”用于离线构造路由标签和评价后悔，不宣称在线额外估计完整结果风险分布。

四个角色分别调用并确定性组合成与RP2教师对齐的四槽卡片。卡片包括状态、已知故障范围、症状、可能原因/机理、检查、维护、限制/冲突、来源和路由结果。每个原子项必须绑定合法Evidence ID与Claim ID。RP2无安全警示教师查询和正例，因此不设置虚假的第五蒸馏槽；安全内容只能是非诊断事实的系统使用边界，或待独立安全教师资产建立后再扩展。

该模式不执行BGE-M3在线编码、ANN全库搜索或大图遍历，但仍按ID访问证据，故称“有界本地证据访问”，不能称为完全免检索。应把节省归因到避免在线编码、32项重排、长提示和7B二阶段核验，而不是声称小图无法放入边缘设备。

### 4.4 四头LEC与训练目标

给定查询表示 $z_q$、候选证据键 $z_i$、元数据 $m_i$ 和可用性掩码 $a_i$，LEC使用四个头：

1. **Pointer/Rank头**：拟合教师完整有界候选分布，张量容量32，实际候选允许0–32，输出K以内证据ID；
2. **Support头**：拟合研究点二两阶段7B的最终二值直接支持掩码；
3. **Field/Underfill头**：输出字段状态和有效基数 $n\in\{0,\ldots,K\}$，负责主动欠填与STOP；
4. **Route头**：根据候选覆盖、支持边际、未知ID、冲突和成本特征选择本地回答、完整教师回退或拒答/人工复核。

不可用证据在指针logit处置为负无穷，解析器再校验ID与记忆哈希。主损失为：

\[
\mathcal L=\lambda_r\mathcal L_{rank}
+\lambda_s\mathcal L_{support}
+\lambda_f\mathcal L_{field}
+\lambda_a\mathcal L_{route}
+\lambda_i\mathcal L_{intervention}
+\lambda_c\mathcal L_{calibration}.
\]

$\mathcal L_{rank}$ 组合温度化列表KL和排序损失；$\mathcal L_{support}$ 使用加权二元损失；$\mathcal L_{field}$ 监督字段状态、0到K基数和集合；$\mathcal L_{route}$ 最小化错误接受、无证据维护动作、时延、能耗和回退费用构成的后悔；$\mathcal L_{intervention}$ 拟合证据删除/干扰下的教师决策变化；$\mathcal L_{calibration}$ 约束概率校准。量化后重新校准支持、停止与路由阈值。

训练分两阶段：先离线模仿冻结教师轨迹，再让学生rollout并由教师纠正学生真实错误，用学生状态分布上的再标注数据减少部署分布偏移。只有在实现多轮聚合并报告策略迭代时才使用“DAgger式”表述。路由标签来自“教师能否实际纠错及其成本”，每条轨迹必须保存回答、回退、拒答三动作的显式反事实成本，不能仅由模型熵或已选动作字段拼接生成。

### 4.5 数据构造、干预与防泄漏

- 必须在精确208底座上重新导出完整有界候选轨迹；现有top-3回放只能用于兼容性检查，不足以训练排序分布。2026-09-06核查显示RP2实际打分池为0–26，32仅为容量上限，禁止填造证据。核心服务器执行状态见 `docs/RP3_COMPLETION_AUDIT_20260906.md`。
- `RP3_TeacherTrace_v1` 保存查询、候选签名、教师排序/支持/停止/动作、成本和全部版本哈希。
- `RP3_RiskBench_v1` 覆盖关键证据删除、同角色异故障干扰、来源重复、范围错配、未知证据ID、冲突/否定、证据不足和分布外问题。合成否定只进入风险集，不作为正向文献证据。
- 先按基础Claim、文档、来源族和故障场景分组切分，再生成改写、负例和干预；所有派生样本继承同一 `base_group_id`，不得跨split。
- 同时报告40个原始CQ、故障—卡片基础场景、独立Claim/文档/来源族/base group数和派生轨迹总数；不能把大量改写当作独立样本，置信区间按基础组或来源族成簇。
- 构建集内部按组隔离的validation用于早停和模型选择；MP008只用于支持阈值、路由阈值与量化后校准，不参与梯度、早停或模型选择；MP009–MP013只用于最终外部评价，不进入训练、增强规则、课程设计、阈值选择或路由校准。

只有LEC观察到候选可用性掩码时，才研究删除关键证据、加入干扰证据的干预一致性。这是对输入证据集合的受控干预，不是现实故障机理的因果效应。

### 4.6 可证明性质与理论边界

1. **契约闭包。** 若指针受可用性掩码约束、解析器只接受冻结ID与哈希、渲染器只呈现Support=direct的指针，则每个输出原子项都能映射到唯一冻结证据。
2. **不可用证据零选择。** 在masked logit为负无穷且解析器二次校验时，不可用证据被选择的概率为零。
3. **风险传播。** 对有界契约损失，可用联合界分解量化LEC相对教师的风险：

\[
R_C(LEC_Q)\le R_C(T)
+\Pr[LEC_{FP}\ne T]
+\Pr[LEC_Q\ne LEC_{FP}]
+\Pr[\text{router misses beneficial fallback}].
\]

4. **路由后悔。** 在动作代价有界时，策略相对最优路由的后悔可由动作分歧概率乘以代价范围上界控制。

这些性质只约束相对冻结教师的证据契约行为。教师相对未知专家事实的风险仍无法由自动标签确定，不能推出事实正确或工程安全保证。当前40条查询及其改写也不足以宣称正式共形风险保证。

### 4.7 实验与工作量

最低必做对照为：RP2 7B教师参考上界、无干预蒸馏LEC、证据移除增强LEC；
