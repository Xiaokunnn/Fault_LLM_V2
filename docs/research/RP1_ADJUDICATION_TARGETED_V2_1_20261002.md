## 1. 当前结论

13 条分歧不能解释为“某个模型错了 13 条”，也不能通过多数投票形成真值。按统一 v2 口径复核，争议涉及条件/模态丢失、动作粒度、知识适用范围及类型/极性错配。原文出现相同词语，并不充分支持被抽取的具体关系；但类型或范围不合适，也不等于原文知识没有用。

本轮已整理 6 页、85 条暂定核心参考和 18 条辅助或未决项，冻结 E0/E1 共 12 个请求。实际执行入口已尝试，因未配置 `DASHSCOPE_API_KEY` 在联网前停止：**真实新 API 调用 0 次，新自动证据合格记录 0 条，主图增量 0 条**。没有新抽取效果数字，不能宣布优化已有效。

“裁定”在这里仅指可审阅的 AI 技术处理意见。13 条真实独立专家裁定仍全部 pending；两轮模型意见与本助手复看都不构成领域专家真值。

## 2. 13 条争议如何处理

完整原文、精确偏移/原生单元、旧三元组及待专家问题见 [逐条复核](../../results/experiments/research_point_1/adjudication_targeted_v2_1/dispute_review.md)。本轮没有重新调用第二意见模型。

| 类型 | 数量 | 记录 | v2 技术处理 |
|---|---:|---|---|
| 条件/模态或标题语境需要补足 | 5 | R021、R047、R039、R063、R015 | 保留源文支持的窄义关系，补足联合方法、材料、阶段、可能性或舱室条件；不视为无条件合格 |
| 动作粒度需要修复 | 2 | R087、R033 | 拆解维护标题或合并检查动作，同时保留步骤和前提 |
| 背景范围及类型错配 | 2 | R010、R009 | 一般可靠性方法、振动接口设计不能直接发布成泵故障维修/检查动作 |
| 主任务范围外 | 2 | R004、R014 | 瞬态分析有文字依据，推进轴系检查也有依据；本段泵应用未成立，不计入泵覆盖 |
| 关系错配 | 1 | R038 | 铭牌是额定电流参数来源，不自动成为诊断方法 |
| 极性错配 | 1 | R037 | “无需维护”保存为负向要求，不发布成正向 maintained_by |

几个需要保留的区别：

- **R021：**流量测定段落提到电流检查、压差读数与泵特性。仅抽“流量→测电流”遗漏联合语境；电流对应流量或功率的句法仍待专家确认，本轮未把它定成已确认正确的独立方法。
- **R039：**启动前检查清单中的 “If … or not” 表示“检查是否”。不能因为出现 if 就自动判断存在丢失的条件前提。新参考继承“启动前检查”，不修改旧筛查器或宣称已经测得其总体误拒率。
- **R063：**保持架破裂与轴不对中的行绑定有原生表格及图像支持，但表头是“可能原因”。新参考保留表头、行单元和原生框，不将可能性升级为必然性。
- **R015：**保留的是直接关联消防泵与海底门舱的进水报警保护；不把整个消防系统扩充为泵知识。必须区分泵在机舱外、同舱且阀锁开、不同舱等条件。
- **R033：**检查有无异常声振本身是源文支持的检查动作；不能因此声称能诊断唯一原因，也不能简单判成没有源文支持。

这些是本轮针对性开发样本的处理数量，不是随机总体误差比例，也不是第二意见模型的准确率。

## 4. 冻结的小批量对照

| 设置 | 固定内容 |
|---|---|
| E0 | 在共享 v2 输出 Schema 下直接逐页抽取 |
| E1 | 同一 Schema 与页面，加上条件、极性、方向、标题/表头与遗漏核对要求 |
| 输入 | 相同的完整源页、原生表格与适用范围元数据，不含旧候选或参考答案 |
| 样本 | 6 页 × 2 臂，共 12 个请求；每对按预定次序交替先后 |
| 模型请求标识 | `qwen3.7-max`，沿用已有配置中的名称；服务可用性尚未验证 |
| 推理设置 | temperature=0，enable_thinking=false，每请求最多 8192 输出 token |
| 输出 | 断言、辅助事实、未决项；断言含条件/模态/极性/范围与原文出处 |
| 重试 | 自动重试为 0；已有成功响应续跑复用，失败/不确定调用停止 |
| 研究资产 | 完整原始响应、请求哈希、返回模型、token、耗时与结束原因分别保存 |

这是一个**联合指令包的开发对照**。E0 不是历史 v4 抽取器的原样重跑，因此新旧总量不能当作严格配对实验。两组只改变核对指令，不能把效果分别归因于其中某一条提示。两组都可表达条件，避免把“有无表示字段”与“是否正确使用字段”混为一个比较。

模型别名不等于不可变权重快照。程序记录并检查返回模型标识；标识一致也不能证明供应商内部权重绝对不变。每页每臂只有一次生成，没有三种子稳定性或总体显著性结论；这里只承担小批量可行性检查。

固定原始请求和协议见 [requests.jsonl](../../results/experiments/research_point_1/adjudication_targeted_v2_1/requests.jsonl)、[experiment_protocol.json](../../results/experiments/research_point_1/adjudication_targeted_v2_1/experiment_protocol.json)。哈希冻结发生在任何新 API 调用之前。

## 5. 如何判断是否值得继续

配对复核至少同时报告：

1. 逐页及汇总的源文支持断言数量、错误/无支持数量。
2. 条件完整的唯一核心参考匹配数量，部分匹配单列，重复表述不重复计数。
3. 背景知识被误当作 primary 的数量，MP002 p89 单独作为范围控制。
4. 未决项、未覆盖参考、重复项、消耗 token 与耗时。

匹配必须同时检查方向、端点语义、条件、模态/极性、适用范围与出处，采用一对一匹配；不能通过拆碎动作、增加回答数量或省略条件取得表面增益。

预设的开发推进条件是：E1 增加条件完整匹配，错误及背景误填均不增加，且已覆盖页面不出现覆盖倒退。未决项影响比较时应判为不确定，不能只删去未决样本后宣布通过。即使通过也仅支持继续验证，不构成独立泛化或部署结论。

正式准确率/召回率要求独立评审者形成源文先行清单、另行裁定输出正确性与匹配、审查参考完整性，并保留真实身份、时间和理由。MP002 的主任务参考分母为 0，召回报告 NA，误填报告数量。未决项单列，不能偷偷当正确、错误或不存在。正式评价不等于运行时逐条专家审批。
