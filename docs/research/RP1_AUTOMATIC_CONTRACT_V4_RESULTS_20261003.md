# RP1 自动源文约束修复 v4 / v4.1 开发实验结果

日期：2026-10-03。**已完成自动化实现、两组离线对照、有限解析补丁及全量复现检查。修订版达到预设的开发改善判据，但正式方法推广、独立专家准确率/召回率和保留页评价仍未成立。**

复用六个已读构建集页面、233条真实输出：E0 103条，E1 130条。没有新增API/教师调用，没有打开29个保留页，没有修改旧图、论文、RP2/RP3教师。协议见 [v4预注册](RP1_AUTOMATIC_CONTRACT_V4_PROTOCOL_20261003.md)，有限补丁见 [v4.1修订记录](RP1_AUTOMATIC_CONTRACT_V4_1_AMENDMENT_20261003.md)。

## 1. 这次与上一轮有什么实质区别

v3 的 C 按候选ID重放本助手逐条编修，只能说明修复潜力。这次实现了纯函数式自动转写器：运行时只接收断言、源页及原生表格、文档适用元数据、Schema和固定筛查器，**不读取候选标签、v3编修答案或参考匹配，也不按候选/文档/页面ID选规则**。

原生单元ID只作定位地址。对全部输出改换候选ID、页面ID及原生单元ID，并逆序重放，语义结果保持一致；运行期间禁止打开文件，检查仍通过。因此这次是可执行的自动机制，不再是逐条编修重放。

覆盖范围仍有限：规则来自这六页的开发错误，只处理声明的英文手册语法族。没有据此证明任意文档泛化，也不能把自动化本身当成新的硕士算法贡献。

## 2. 两个机制对照与保留的失败

- **P0：源文上下文。**补章节、编号步骤、材料/轴承架适用条件、维护停机前提，按原生列继承原因模态，保留有泵型限定的轴承范围；将无需维护、运行机理/操作等转存旁路。
- **P1：P0加角色绑定。**区分受检对象与仪器，修正唯一可绑定的检查目标；区分要进行的操作与要预防的不良事件，修正部分检修动作归属。多个对象或部件名称冲突时隔离。

两组都执行同一旧筛查器，不从参考或原辅助响应补造新断言。每个输入最多一个输出。原A/B只读复用，原C仅为开发诊断参照。

首轮 v4 **整体FAIL**：E1的 `VR11:A011` 原本是“检查管路是否紧固/供水正常”，条件解析却把 `If ... or not` 当作必须已满足的前提，违反“不得新增放行损坏原本正确知识”的判据。另有两条旋向条件被 `i.e.` 的句点截断。

保留v4全部代码、466条输出与评价后，另存v4.1，只修上述两个解析缺陷：是否检查不继承为前提，括号内缩写不终止句子。没有改变Schema、阈值、参考分母或联合判据。实际只有预先声明的**4个输出**改变，其余**462个输出逐值相同**。不能把这次补丁后的通过写成首轮一次成功。

## 3. 质量与数量一起看

以下均为本助手另存的源文技术复核，**不是独立专家标签**。改变过的输出没有因为通过自身筛查就自动判为正确。原本完整、未改变语义的记录复用旧技术标签；变更部分按源文逐项复核。

“问题”含表示错误、条件不完整、语义错误；未决另计。完整核心要求primary范围、关系与对象支持、条件和模态完整。两臂来自同一批页面，不能相加作新图规模。

P1相对旧B，两臂完整知识保留量和参考匹配增加，问题加未决放行不增加，正确知识损失不增加，没有新放行损坏原本正确的核心记录；MP002背景页没有primary误填。实现不变性检查亦通过。**所以修订版通过的是预先固定的“相对旧B的开发改善”判据。**

这不意味着所有输出正确：P1仍有E0的9条问题+1条未决、E1的8条问题+3条未决被机械放行。此外，核心之外仍有1/8条问题记录（包括背景、结构关系和旁路），没有用转存旁路掩盖这些问题。

P1也不全面优于P0：它多恢复了两臂5/6条完整知识及5/6项完整参考，但E0多误拒1条本来正确的灌液检查。该条引用包含两个检查对象，非唯一绑定屏障隔离了它；这是明确的保留量代价，不能只报新增量。

## 6. 尚未解决的问题与新的审计发现

1. **因果与条件。**低扬程→流量上升→功耗/汽蚀仍有直接邻接混淆；关阀运行的最大允许值不等于超限风险条件；汽蚀表现与导致侵蚀仍不能随意互换。没有为了数字好看改写这些剩余条目。
2. **程序完整性。**排液动作归属修好了，但排液通道及冷热排液安全条件未完整恢复；Back Pull Out实际移除步骤因包含交叉引用，被旧筛查器过度拦截。恢复运行旁路还继承了过宽的维护停机条件。
3. **多对象引用。**`VR08:A013` 本来正确，但与其他检查项目共用引用，被非唯一绑定规则隔离；未来需先分离句法命题，再绑定对象，而不是直接放宽隔离门。
4. **核心之外的问题。**near不等于located_in；提供冷却功能不等于结构contains；通用可靠性参数也不自动成为被趋势方法诊断的故障。这些仍在错误清单中。
5. **不能把v3人工式编修当真值上界。**本次复核发现 `VR12:A009/A010` 从位置变为维护动作后，仍保留descriptive/possible模态，程序要求表达不完整；v3 C也遗留同一问题。原C及其旧报告不覆盖，本轮将问题明确列出，不以旧C“全部完整”作为成功目标。

## 7. 对硕士研究点意味着什么

这次建立了可重复运行的组件，并证明章节/表头/角色约束在已阅开发材料上可以恢复知识，同时显示拒绝与修复的实际权衡。它比“筛掉更多记录”更接近兼顾可用数量的方向。

但目前仍是有限语法规则转写。运行不读标签、ID不变性和局部回归测试是实现正确性的证据，不能替代独立效果评价，也不能自动构成算法创新。若继续形成论文方法，需明确：条件与例外的作用域如何组合、哪些修复由证据唯一确定、何时保持未决，以及保留量与错误放行的联合目标；再与匹配约束能力的过滤/修复基线比较。

当前可以冻结v4.1作为**开发候选实现**，不能宣布正式方法已验证或扩大图谱。下一步优先让独立评审核对源页参考和关键争议，同时针对残余机制预先固定下一实验；不要继续无记录地叠加针对六页的规则。参考确认、方法冻结和独立评价条件满足后，再按原协议打开保留页。
