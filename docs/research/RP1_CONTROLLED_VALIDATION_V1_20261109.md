日期：2026-11-09。范围：固定10个既有构建集开发目标页，不重构主流水线，不扩图，不启动联合优化。

## 1. 当前能做什么

用户已说明没有现成的人工参考。本轮先交付源文标注包和可执行的损失统计工具。
人工参考未完成前，不计算或声称正式候选召回率，也不把旧AI清单改名为人标。
人标用于离线研究评价，不参与原图谱逐条准入，因此不改变RP1“无需逐条人工审批”的方法边界。

2. **原编译器**：同一批次自动通过的107条，原记录不改写。用于测量原始正确候选在编译/准入检查中的损失。

## 3. 先形成源文参考

标注范围固定为冻结Schema中的11类核心诊断关系：

`occurs_at`、`causes`、`indicates`、`manifests_as`、`evolves_to`、`diagnosed_by`、
`inspected_by`、`mitigated_by`、`prevented_by`、`maintained_by`、`increases_risk_of`。

“所有可抽取目标关系”指上述明确范围内的原文原子关系，不是全文所有名词对、部件目录或规格参数。
关系端点类型与方向仍遵守冻结Schema。常规安装、运行步骤不能为了增加数量全部改成故障维护知识。
没有明确故障时，不把一般设备监测强行附着到某个故障节点。

人工先只读`source_only/`，逐页穷举该范围内原文明确支持的关系，不先看候选与放行状态。
每条参考保留头尾、类型、关系、适用对象、条件、否定、模态及原文锚点。
同页同义重复合并；条件或适用范围不同的关系分别记录。不同因果层级不得直接做传递合并。
零目标页写明理由后保留；表格角色或跨页条件看不清时记录未决，不猜测。

机器只检查字段、类型和引文回读；标注是否语义正确、穷尽，仍由标注者负责。
`reviewer_kind: human`是来源声明，不是程序对评阅人身份或领域资质的认证。
旧AI清单既非穷尽，也非人标；本轮prepare不读取它们。

## 4. 第二步：对候选作完整/近似匹配与缺陷标注

源文参考封存后，`seal`才导出候选判读表。
表中混排原始和最新B0的载荷，隐藏方法名、放行状态和历史AI标签。
这只减少本轮判读时的标签提示，不表示评阅人对项目历史完全盲。

每条原始候选都要判读，包括原编译器拒绝项；最新B0的改写载荷也要单独判读。
候选状态包括完整匹配、角色错误、方向错误、条件不完整、证据不足、源文不支持、范围不符及未决。
完整匹配必须指定一项参考ID；有缺陷但与某参考有关时填写最近参考ID，不把近似表达计为完整召回。
一条原子候选至多完整匹配一项参考，多条候选命中同一参考只计一次覆盖。

主因以参考关系为单位记录：

- RAW已有完整表达且原编译器保留：保留。
- RAW已有完整表达但原编译器未保留：编译/准入拒绝损失，结合原flags继续解释；不能仅据此宣布某个核验器过严。
- RAW只有近似表达：根据角色/方向、条件、证据等缺陷定位，所有并存缺陷另存，不将主因计数相加成多条知识。
- RAW没有完整或相关近似表达，且该页全部原始候选均已判读：未生成。
- 仍有无法排除的未决候选：未决，不断言为“从未生成”。

## 5. 统计口径

对人标参考集合G、原始候选的完整匹配集合H_raw、原编译器完整匹配集合H_keep：

```text
原始候选召回 = |H_raw| / |G|
原流水线召回 = |H_keep| / |G|
条件过滤损失 = |H_raw − H_keep| / |H_raw|
绝对损失比例 = |H_raw − H_keep| / |G|
```

零目标页的单页召回为NA；|H_raw|为0时条件损失为NA。
候选未决时，确认召回给出下界，可能覆盖的上界另报，不能把未决当作确定错误。
最新B0另报`H_latest − H_raw`和`H_raw − H_latest`。
同时报告各候选集完整匹配数、记录级精确率、重复数、错误类型和未决数，不只看最终保留数量。

本轮10页是开发诊断，不进行总体知识召回外推。
页与文档存在依赖，不能用162条候选当162个独立样本做显著性检验。

## 6. 诊断之后才实现的单机制对照

当前暂不编写新候选恢复规则和角色评分权重，避免在不知道主要损失位置时同时堆机制。
工具完成损失账本后，按实际主因决定先验证哪一项；若两项都值得检验，采用下表分解。

| 组 | 原始候选池 | 独立证据恢复 | 角色敏感评分 |
| --- | --- | --- | --- |
| B | 固定原始池 | 无 | 无 |
| R | 固定原始池 | 有 | 无 |
| S | 固定原始池 | 无 | 有 |
| RS | 固定原始池 | 有 | 有 |

恢复路径只能读取原文结构和既定Schema，不能读取人工参考、缺失关系ID或候选判读标签生成答案。
角色敏感评分必须体现端点角色、关系方向及原文条件；模式合法性或名词共现本身不当作语义支持。
R/B检验恢复作用，S/B检验评分作用，RS/R和RS/S分别隔离另一机制的贡献。
若只做RS对B，无法说明改进来自哪里。

每个新方法在执行前另行冻结具体实现及预算。本轮准备允许新模型调用0次。
若选择离线恢复，原模型响应复用，各组保持相同的下游候选/核验名额，新增CPU开销单独计量。
若恢复需要额外LLM调用，必须给基线相同调用与词元预算，不能与零额外调用的基线直接宣称等资源。
历史API耗时、缓存读取耗时和新在线推理耗时分开，缓存时间不冒充模型加速。

主要看固定预算下新增完整参考覆盖、旧正确关系丢失、错误放行数量及条件/方向错误。
全池结果和数量—质量曲线同时报告，不能仅靠少输出换取高精确率。
无法被当前开发页覆盖的关系类型不作机制有效性结论。

开发中出现实质收益后，才可另行冻结小规模未用于开发的构建页验证。
稳定增益需在这些页上仍成立；当前10页的提升不能直接称为统计显著或独立泛化。
如果某机制没有净恢复完整知识，或新增错误抵消收益，停止该机制，不带入联合优化和大规模实验。
