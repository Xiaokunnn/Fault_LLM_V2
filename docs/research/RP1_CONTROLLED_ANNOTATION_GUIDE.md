# 固定10页的人工标注说明

本轮先解决“参考关系是什么”，再看模型生成了什么。
打开`results/experiments/research_point_1/controlled_validation_v1_20261109/source_only/`，按01到10逐页阅读全文。
不要先打开private目录中的模型候选。每页前半部分列出原文，后半部分列出原生正文块/单元格地址。
若表格文本无法确定对应关系，需查看原PDF及物理页；不得根据模型曾经输出过什么猜测答案。

## 每页需要完成的工作

1. 阅读目标页和已提供的上下文，找出核心诊断关系。上下文独有知识不计入该目标页。
2. 每条关系写清楚“谁—什么关系—谁”，保留条件、否定、可能性、型号和操作阶段。
3. 同页同义重复合并；一段中若有不同原子关系，分别标注，不做传递推理。
4. 从原生块/单元中复制支持引文，并写对应地址。
5. 检查是否遗漏。确实没有目标关系的页面写理由，不删除该页。
6. 无法确定的内容写入`unresolved_notes`，不要填成错误或默认正例。

## 填写文件

编辑`annotations/page_annotations.jsonl`。它是10行JSON，每行对应一页。
`reviewer_id`填写真实标注者代号，`coverage_complete`仅在该页已完整检查后改为`true`。
`targets`保存全部目标关系；没有目标时保留空列表，并填写`zero_target_reason`。

一项关系的格式如下。**这是格式示意，不是本轮真实标注，请勿直接复制为样本答案。**

```json
{
  "reference_id": "自定的全局唯一编号",
  "head": "源文中的原因/设备/故障等对象",
  "head_type": "与关系定义兼容的实体类型",
  "relation": "冻结关系名",
  "tail": "源文中的结果/检查/操作等对象",
  "tail_type": "与关系定义兼容的实体类型",
  "conditions": ["原文明确限定的条件；没有则使用空列表"],
  "modality": "asserted/possible/required等实际模态",
  "polarity": "positive或negative",
  "applicability": "设备对象、型号或适用阶段",
  "evidence": [
    {"unit_id": "从源文包复制的正文块或表格单元ID", "quote": "从该单元逐字复制的支持引文"}
  ]
}
```

通常不必人工填写字符偏移，程序会对唯一引文自动回读。
同一引文在同一单元重复出现时，才需补充`start/end`，采用该单元内左闭右开偏移。
跨多个真实单元的证据写多个锚点，不能将拼接后的句子伪装为一个连续原文位置。

## 核心关系与类型

准确的方向和允许端点类型见产物`private/relation_registry.json`；它是Schema，不含模型候选或评价标签，可在源文标注阶段查阅。
范围包括：发生部位、原因、指示、表现、演化、诊断/检查方法、缓解/预防/维护以及风险增加等11类核心关系。
不包含纯部件目录、尺寸参数或任意两个名词之间的共现关系。

遇到类型归属无法确定，先记未决，不为了通过机器校验强行改成某种类型。
这些人标只构成本轮离线评价参考，不是为旧图谱进行逐条批准。

## 参考封存后的候选判读

执行`seal`成功后才会出现`annotations/candidate_reviews.jsonl`。
每行含一个匿名载荷和原页标识，请填写`reviewer_id`、`verdict`、匹配关系以及源文理由，不修改候选载荷。

| verdict | 使用方式 |
| --- | --- |
| complete | 整条关系及条件、方向、范围均完整；`reference_id`填写一项参考编号 |
| wrong_role | 对象或动作角色错误；`related_reference_ids`填写其本应表达的参考编号 |
| wrong_direction | 原因/结果或关系方向反了；填写最近参考编号 |
| partial_conditions | 主体关系接近，但条件、模态、否定或范围不完整；填写最近参考编号 |
| insufficient_evidence | 关系接近某参考，但该候选绑定的引文/位置不够；填写最近参考编号 |
| unsupported | 源文不能支持此载荷；如它是某参考的错误表达，仍填写最近参考编号 |
| out_of_scope | 超出固定的目标范围；不计入完整目标匹配 |
| unresolved | 目前无法确定，保留未决，不硬判正负 |

不完整关系的`reference_id`保持`null`，关联参考写到`related_reference_ids`，避免被误计成完整召回。
如果原始候选均无任何完整或近似对应，统计程序才有依据将一项参考归为“未生成”。
一条原子候选不能当作多项完整参考，重复候选也不会重复增加召回。

程序仅核对填报完整性与位置恢复，不能自动确认评阅人是否是真人、是否具有领域资质，或语义判断是否正确。
