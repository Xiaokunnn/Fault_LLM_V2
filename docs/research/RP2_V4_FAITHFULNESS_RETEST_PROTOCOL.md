# 研究点二 v4：证据约束生成与忠实性复测协议

更新日期：2026-08-04  
标签边界：全部为 Silver，never Gold；无领域专家审核。

## 1. 目标

本轮不通过更改 Silver 标签、删除困难查询或事后改变指标公式获得高分。v4 将开发集的算法与评价协议在重跑前固定，同时检查：

1. Ours 在不读取 `fault_class_ids` 和 `relevant_evidence_ids` 的条件下，能否提高引用证据的故障对象一致性。
2. 证据约束生成与轻量忠实性守卫能否减少自由改写、对象偷换和摘要新增事实。
3. 质量提升是否在本地 Qwen2.5-7B 的 p95 端到端时延不劣于 Dense K4 5% 的条件下实现。

## 2. 算法修改

### 2.1 可见语义故障亲和度

对查询故障名称 (q_f) 与候选主张两端中文实体 (h_i,t_i) 计算：

\[
A_f(q,i)=\max\{\operatorname{Dice}_{2g}(q_f,h_i),
\operatorname{Dice}_{2g}(q_f,t_i)\}.
\]

Ours v4 先用开发复测前固定的可见语义下限 `A_f>=0.03` 移除故障对象不一致的候选，再计算候选分数：

\[
s_i=s_i^{dense}+\lambda_gs_i^{graph}+0.1c_i+\lambda_fA_f(q,i),
\]

其中开发复测前固定 `lambda_g=0.24`、`lambda_f=0.35`。亲和度只使用查询文本与发布图的中文实体名，不使用评价标签。若没有候选通过下限，v4 返回空证据而不用无关故障候选填充预算。

### 2.2 证据约束生成

本地 7B 不再被要求自由综述所有候选，而是选择直接匹配故障对象与问题角色的最小证据集。每个回答点只允许一个主证据 ID，禁止跨证据拼成新事实。

### 2.3 轻量忠实性守卫

守卫不调用第二次大模型，只执行：

- 证据 ID 白名单、问题角色和可见故障亲和度检查；
- 一个原子回答点绑定一个主证据；
- 根据已发布 Silver 规范主张保守渲染中文回答点；
- 摘要只拼接通过守卫的原子回答点，不生成新命题；
- 无合格回答点时回退为“证据不足”。

守卫的毫秒级耗时被计入端到端时延，因此不会把后处理开销隐藏在性能统计外。

## 3. Judge v2

Judge v2 仍使用同一 `qwen3.7-max` 的两个独立提示角色，因此只能称为双提示 Silver 语义审计，不是独立人工审核。与v1相比，其不再把多条证据原文先拼接再验证一段引文，而是要求每个引文片段绑定具体 `evidence_id`，逐条验证其为该证据原文的连续片段。

报告分解为：

- 原子回答点严格支持率；
- 摘要严格支持率；
- 已回答样本的全原子主张严格支持率；
- 保留的旧“全文本严格支持率”。

这是对旧验证缺陷的技术修正，不放宽 `supported` 的语义标准。

## 4. 固定场景与门槛

同一轮复测包含：

- `B1_dense_k4_guard`：Dense K4 + 相同生成器和守卫；
- `B4_metapath_k3_guard`：Metapath K3 + 相同生成器和守卫；
- `A_guard_ours_v4_k3_no_guard`：Ours v4 K3，去掉生成后守卫；
- `Ours_v4_k3`：完整方法。

预注册就绪门槛为：`P>=0.80`、预算归一 `F1>=0.65`、双提示严格点支持率 `>=0.60`、全原子主张严格支持率 `>=0.30`、保留的全文本严格支持率 `>=0.30`、可回答回答率 `>=0.85`、不可回答拒答率 `>=0.95`、合同合格率 `>=0.95`，且 Ours v4 K3 的 p95 时延不高于 Dense K4 的 1.05 倍。

这些是本项目的论文就绪目标，不是领域通用标准。如未达标，应报告失败门槛，不得事后换公式或隐去已预注册的核心指标。

## 5. 执行顺序

```bash
git pull --ff-only origin main
source .venv/bin/activate

# 先冒烟，只跑前2个查询
bash scripts/run_rp2_faithfulness_v4_server.sh --limit 2 --force-generation

# 冒烟通过后删除v4冒烟输出，再跑40查询正式开发复测
rm -rf results/experiments/research_point_2/graphrag_v4_faithfulness
bash scripts/run_rp2_faithfulness_v4_server.sh --force-generation

# 对四种方法的回答执行Judge v2，密钥隐藏输入
bash scripts/run_rp2_semantic_judge_v2_secure.sh
```

`--force-generation` 用于获得新一轮真实时延；如运行中断，去掉该参数重跑可复用已完成缓存，但缓存响应的请求墙钟时间不能用于新时延结论。
