# RP1 源文约束自动修复 v4 开发实验协议

日期：2026-10-03。在任何 v4 批量推理及结果汇总前固定。输入为既有六页完整源文及 E0/E1 共233条断言；不增加API调用、不打开29个保留页、不修改旧图/教师/论文。

## 1. 目的与固定对照

v3 的 C 是按候选 ID 重放 AI 编修，不能作为自动算法。本轮实现只接受候选字段、源页结构、文档适用元数据及冻结 Schema 的纯函数；不读取文件、网络、候选 ID、文档/页面 ID、人工标签、v3 修改账本或参考匹配。原生单元 ID 仅用于定位，替换其名称且保持引用对应时行为必须不变。

复用 v3 A 原始输出和 B 仅筛查，不重算/改写其文件；C 只作非独立的编修参考。新运行两个确定性对照：

- **P0 context**：绑定真实源文，识别编号拆装程序/步骤/前提及交叉引用；继承原生故障表的列模态和有泵型限定的适用范围；保存负向维护、运行操作、机理等旁路；补有明确语法连接的维护停机及局部条件。对识别出的来源/部件歧义隔离。完成后执行冻结 B 的机械筛查。
- **P1 roles**：在完全相同 P0 基础上，增加受检对象与仪器区分、启动检查的唯一源对象绑定、操作目的与被预防事件区分，以及有唯一语法绑定的检修动作归属。不能绑定或有多个候选时隔离/保留待评，不强改。

两组都最多一个父候选一个输出，不从参考或原辅助响应补造新核心记录。规则只覆盖预声明的英文手册语法族；不是通用自然语言蕴含器。六页已经被用来开发，不能声称新样本泛化。

## 2. 理论与出处边界

为候选构造源文支持的有限表示集合：原断言、章节/表头作用域补全、唯一语法角色绑定、辅助要求以及未决。出处不变、条件不弱化、模态与否定不翻转是可行性约束；在允许规则内优先保持原内容，唯一可确定修复时采用修复，冲突时保留未决。

此实现是确定性、有限语法的约束转写，不冒称解决完整最小编辑优化，也不把规则或简单形式化包装为已验证理论创新。每条变更保存原值、新值、规则号与来源片段；多个证据片段独立定位。原生单元保留真实表/行/列和 bbox，页面文本不制造 bbox。条件正文和程序次序允许作为结构化子记录保存，但不能宣称单步是完整维修方案。

## 3. 预先固定的评价口径

使用 v3 未改动的85项总账/79项暂定核心参考与旧技术标签。新输出不能仅因通过自身规则就判正确：保持不变的部分沿用旧标签，变更部分由本助手另存逐条源文技术复核；这仍不是盲审/独立专家。技术评价账本与运行模块隔离，运行时禁止读取。

分别报告两提示臂：条件完整核心记录（及精确文本去重）、表示/条件/语义错误放行、未决放行、原本正确记录被拒、辅助内容保留量、一对一完整参考匹配及逐页覆盖。表范围重分类另列；同一复合输出最多完整覆盖一参考。保留全部原参考分母及未决，不在看结果后改指标。

**开发联合判据（预注册，不能事后改成更容易的条件）：**P1相对旧B，在E0与E1各自均需满足：

1. 条件完整核心精确去重量不减少，完整参考匹配不减少；两臂完整参考匹配均严格增加。
2. 已知问题与未决核心放行总数不增加；原本条件完整核心记录的拒绝/损坏数不高于B；新增语义损坏的原本正确核心记录为0。
3. 不计 background→primary 的条目后，完整参考匹配仍高于B，防止仅靠范围改判过关；MP002主任务误填保持0。
4. 输入顺序/候选ID/页ID及原生定位ID变换不影响语义输出；出处、原产物与可复现性检查通过。

P1与P0另报机制贡献，不因其结果回调参数。任何假设/判据失败都保留；开发通过也不自动授权保留页或发布。

## 4. 后续门

代码先做合成正/负边界测试，冻结后批量执行一次。实现错误修正需留记录，禁止看开发质量改规则再称预设结果。正式方法推广还要求独立参考评审、未决裁定和未看过的保留页评价。当前无独立专家，故本轮无论开发判据是否通过，均不开保留页、不扩大抽取、不宣称正式准确率/召回率、工程有效性或新增论文算法贡献已成立。
