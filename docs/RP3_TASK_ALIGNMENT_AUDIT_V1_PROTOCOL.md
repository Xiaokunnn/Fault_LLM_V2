匹配的模型响应缓存、干预核验记录、冻结RP2配置和此前的支持冲突审计。
原始40条、派生125条分别报告，分组仍继承10个故障类别场景，不能称165个独立病例。
MP008与外部文档不进入内容分析；全目录保存性检查仅计算原文件字节哈希。
不加载模型、重算特征、调用教师、拟合阈值或改变任一历史标签/划分。

新结果只写`results/experiments/research_point_3/task_alignment_v1/`，输出目录已存在则拒绝执行。
输入清单包含路径、SHA256；逐条输出关联到源文件、轨迹ID、原核验fingerprint及实际缓存路径。
用户的`deep-research-report-rp3.md`原稿保持原样；更正和方法决策写入独立审计报告。

## 审计问题和口径

1. **标签与最终集合**：恢复真正送入核验器的有序K≤3集合；逐条比较第一阶段、召回复核、最终
   support、确定性guard和导出指针。分别统计支持正但未选、负而被选、未评估、不可用候选。
   构造“全池已保存正标签取前3”仅检验标签语义，不是可运行方法或新性能成绩。
2. **监督来源**：原K3批核验、原尾部单证据核验、增强K3重新核验、继承原K3/原尾部标签分别计数。
   特别检查未重新入选的证据是否继承了原批核验，而非误称全部来自单证据监督。
3. **冲突追溯**：按查询可见文本/角色/故障范围和证据ID分组，复核之前10/3个点式输入冲突。
   比较实际保存的用户提示词、候选顺序/位置和单证据复核；继承标签追溯到原标签产生的上下文。
   相同提示词记录的一致性只针对已有缓存，不推出教师全局确定性或上下文变化的唯一因果解释。
4. **查询族覆盖**：报告原始查询、故障类别场景、请求角色及把给定故障名称替换为占位符后的
   文本模板。模板只是可复查的表面查询族代理，不冒充独立语义意图/真实运行病例。
   统计train/validation候选及选中证据、Claim、文档、来源族交集，区分场景隔离与语料隔离。
5. **下一步决策**：区分“模仿现有两阶段K3教师的最终mask”与“独立点式直接支持语义”。
   后者不能直接把混合上下文标签重新命名为真值；不删除冲突行来制造改善。
   仅形成输入/对照/停止条件建议；数据协议和独立场景覆盖未解决前，不开始新训练。

## 正确性检查

- 核验manifest数据哈希、冻结候选身份、原始轨迹在增强包中的一致性及父子分组。
- 用冻结的确定性选择和guard代码重建符号结果；不执行embedding或7B推理。
- 原响应、mask、review与缓存逐项对应；无缓存的零候选NO_CALL单独检查。
- 复核旧冲突组的(轨迹ID,证据ID,标签)及经验最少错误数，不依赖新模型输出。
- 合成测试覆盖“正但未选”、未评估、继承批标签、同提示词冲突及查询族计数。
- 对运行前既有研究文件和日志核对哈希；公开限制和任何核验失败。
